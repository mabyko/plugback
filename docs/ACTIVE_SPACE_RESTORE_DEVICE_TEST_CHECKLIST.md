# 안내형 Space 복원 실기기 체크리스트

> 현재 제품 흐름: 잔류 Space 감지 → 출발·목적 화면 안내 → 사용자가 한 번 이동 → 필요하면 한 번 방문 → Plugback이 대상 표준 창 위치 복원.

이 체크리스트는 제품 Release 빌드를 판정한다. DEBUG Space write 프로브의 과거 성공·실패는 제품 동작의 성공으로 세지 않는다.

## 판정 원칙

- Plugback이 직접 바꿀 수 있는 것은 대상 앱의 표준 창 frame뿐이다.
- Space 이동·생성·삭제·순서 변경, Mission Control 입력 합성, `AXFullScreen` write가 한 번이라도 있으면 실패다.
- snapshot·identity·membership을 확실히 알 수 없으면 무동작이 정답이다.
- `SlotSpaceOverlay`는 메모리 전용이다. 앱을 재시작하거나 Release를 교체하면 기준 배치를 다시 저장한다.
- 처음부터 목적 화면에 있던 비활성 Space 방문은 복원하지 않는 것이 정답이다.

- [ ] 설정 창에 「일반 Space 복원」과 「전체 화면 복원」 메뉴가 없음
- [ ] 제품 코드에 Space write·Mission Control 합성 입력·`AXFullScreen` write가 없음
- [ ] 손쉬운 사용 권한 허용
- [ ] Plugback과 테스트 앱 외의 자동 창 관리 도구 잠시 중지

## 1. 기준 프로필 만들기

외장 화면 A에 일반 Space 두 개를 준비한다.

- Space 1: Finder 표준 창, 왼쪽 절반
- Space 2: Zed 또는 다른 대상 앱의 표준 창, 오른쪽 절반

- [ ] Space 1에서 `[💾 지금 레이아웃 저장]`
- [ ] Space 2에서 같은 버튼을 다시 눌러 두 Space binding을 한 수동 슬롯에 합침
- [ ] 카드에 `Space 1`, `Space 2`가 저장 순서대로 보임
- [ ] 각 Space에서 현재 앱과 위치를 캡처해 기준 이미지 보관

자동 슬롯을 검증하지 않는 회차는 OFF로 둔다. 안내형 복원은 자동 슬롯과 무관하다.

## 2. 잔류 감지와 이동 안내

1. Mission Control을 연다.
2. 저장한 Space 하나를 외장 화면 A에서 내장 화면으로 직접 옮긴다.
3. Mission Control을 닫는다.
4. 자동 모드라면 A를 분리·재연결한다. 수동 모드라면 `[⚡ 지금 레이아웃 복원]`을 누른다.

- [ ] Plugback이 Mission Control을 자동으로 열지 않음
- [ ] pointer·keyboard가 움직이지 않음
- [ ] 해당 행이 `이동 필요`로 표시됨
- [ ] 안내에 실제 출발 화면 이름과 A의 이름이 `출발 → 목적`으로 표시됨
- [ ] 잔류 Space나 그 창이 Plugback 때문에 움직이지 않음
- [ ] 다른 저장 Space, 대상 아닌 앱, 내장 화면의 다른 창이 변하지 않음

판정 실패:

- 화면 이름이 뒤바뀜
- live-but-unsaved Space가 새 `Space N` 행으로 생김
- Plugback이 Space 자체를 움직이거나 Mission Control을 조작함
- 잔류 Space 앱 창만 평면 좌표 복원으로 내장 화면에서 움직임

## 3. 사용자 이동 뒤 방문 안내

1. 안내된 대로 Mission Control을 연다.
2. 잔류 Space를 출발 화면에서 외장 화면 A로 한 번 옮긴다.
3. 그 Space를 열지 않은 채 Mission Control을 닫는다.

- [ ] `이동 필요` 안내가 사라짐
- [ ] 창이 있는 Space는 `열면 복원`으로 바뀜
- [ ] 목적 화면 이름이 방문 안내에 표시됨
- [ ] 아직 해당 창 frame 복원은 일어나지 않음
- [ ] 다른 Space의 창과 자동 슬롯 후보가 중간 배치로 바뀌지 않음

## 4. 한 번 방문 뒤 자동 완료

1. `열면 복원`으로 표시된 Space를 외장 화면 A에서 한 번 연다.
2. 추가 버튼 입력 없이 정착 간격을 기다린다.

- [ ] 해당 recovery에 묶인 대상 표준 창만 저장 좌표로 복원됨
- [ ] 최소화·전체화면·대상 아닌 창은 그대로임
- [ ] 안내가 사라지고 행 상태가 `현재`가 됨
- [ ] 같은 Space를 다시 나갔다 들어와도 추가 복원이 일어나지 않음
- [ ] 창 이동 결과의 성공·건너뜀·실패가 카드 결과에 표시됨

자동 모드와 수동 모드에서 각각 한 회차 실행한다. 차이는 recovery 시작 방법뿐이어야 하며, 시작 뒤에는 둘 다 자동으로 이어져야 한다.

## 5. 일반 방문 복원이 없음을 확인

1. 저장된 Space를 외장 화면 A에 그대로 둔다.
2. 그 Space가 현재일 때 대상 창을 저장 좌표와 다른 곳으로 옮긴다.
3. 다른 Space로 전환해 대상 Space를 비활성으로 만든다.
4. `[⚡ 지금 레이아웃 복원]`을 누른다.
5. 대상 Space를 한 번 방문한다.

- [ ] 복원 시작 때 해당 Space에 `열면 복원` 안내가 생기지 않음
- [ ] 방문 뒤 Plugback이 창을 저장 좌표로 자동 복원하지 않음
- [ ] 사용자가 다시 복원 버튼을 눌렀을 때 현재 Space의 창만 정상 복원됨

이 항목이 실패하면 제거하기로 한 일반 Space 방문 복원이 남아 있는 것이다.

## 6. 전체화면·Split View 비침해

1. 대상 앱 하나를 native fullscreen으로 만든다.
2. 가능하면 별도 앱과 Split View도 만든다.
3. 자동 연결 복원과 수동 복원을 각각 실행한다.

- [ ] 전체화면·Split View 상태가 해제되거나 재생성되지 않음
- [ ] 화면 소속과 순서가 바뀌지 않음
- [ ] 전체화면 대상은 `전체화면이라 건너뜀`으로 보고됨
- [ ] 설정 창과 카드에 전체 화면 복원 기능이나 그룹이 없음

## 7. fail-closed

다음 중 가능한 조건을 만들어 복원한다.

- Space snapshot 판독 실패
- 같은 opaque name 중복
- membership이 0개 또는 복수
- 저장 Space가 사라짐

- [ ] 대상 창이 평면 복원으로 강등되어 움직이지 않음
- [ ] `현재 상태를 확실히 확인할 수 없어 창을 옮기지 않았습니다` 또는 상태 확인 불가 표시
- [ ] snapshot 판독 실패 중 저장을 눌러도 기존 Space 그룹·앱 좌표가 바뀌지 않고 `Space 상태를 확인하지 못해 저장하지 않았습니다`가 표시됨
- [ ] 같은 상태에서 대상 앱을 체크하거나 자동 수집 이벤트가 와도 기존 binding·후보·마지막 수집 시각이 유지됨
- [ ] crash·Mission Control 자동 실행·반복 polling 없음

## 8. 자동 슬롯과의 순서

자동 슬롯을 ON으로 바꾸고 잔류 회차를 반복한다.

- [ ] recovery가 `이동 필요` 또는 `열면 복원`인 동안 수집 시각·후보가 중간 배치로 바뀌지 않음
- [ ] recovery 완료 뒤 현재 실제 배치만 수집됨
- [ ] 자동 슬롯 OFF에서는 Mission Control 닫힘이 후보나 파일을 바꾸지 않음
- [ ] 화면 분리 확정은 이미 모은 후보만 쓰고 창을 새로 읽지 않음
