# 코드·아키텍처·UI 검토

2026-09-05. 현재 체크아웃 기준. 실제 앱 소스는 변경하지 않았다.

코어와 macOS 어댑터의 분리는 유지하고, 오류 처리 → 화면 표현 계산 → 카드 구성 순서로 개선하는 것이 적절하다. 파일 길이만으로 엔진을 다시 나눌 필요는 없다.

## 먼저 고칠 동작

### P1. 손상 프로필의 백업 실패가 성공으로 처리됨 — 재현 확인

- 위치: `Sources/PlugbackKit/ProfileStore.swift:49`, `Sources/PlugbackKit/ProfileSlots.swift:112`.
- `moveItem` 실패를 `try?`로 버린 뒤 무조건 `corruptionBackedUp`을 반환한다. 슬롯은 `.unreadable`일 때만 저장을 막으므로, 백업되지 않은 원본을 다음 저장이 덮어쓸 수 있다.
- 초 단위 백업 이름이 이미 존재하는 조건을 임시 디렉터리에서 만들고, 실제 `Model.swift`·`ProfileStore.swift`를 컴파일해 확인했다. 백업 경로에는 기존 파일이 남고 원본도 남았지만, 반환값은 백업 성공이었다. 이어진 저장은 원본을 덮어썼다. 사용자 프로필은 사용하지 않았다.
- 최소 수정: 백업 이동 실패는 `.unreadable`로 반환해 기존 저장 차단 경로를 재사용한다. 백업 이름 충돌 방지는 별도로 UUID 등을 붙일 수 있지만, 실패 처리 자체를 대체할 수 없다.
- 검증: 기존 `ProfileStoreTests`에 백업 이동 실패 시 원본 보존·저장 차단을 확인하는 회귀 테스트를 추가한다. 현재 테스트는 백업 성공만 확인한다.

### P2. 로그인 자동 실행 토글이 실제 상태와 달라질 수 있음 — 코드 확인

- 위치: `App/Plugback/LoginItem.swift:8`, `App/Plugback/SettingsView.swift:58`.
- 화면은 요청한 값으로 `launchAtLogin`을 먼저 바꾸고 등록·해제 오류는 버린다. 실패해도 토글은 성공한 모양으로 남으며, 설정 창을 다시 열어야 실제 상태가 보인다.
- 첫 실행도 등록 전에 `didConfigureLoginItem`을 기록하므로 일시적인 실패를 완료로 취급한다.
- 최소 수정: 등록·해제 결과를 반환하고 실제 상태로 토글을 맞춘다. 실패나 사용자 승인 필요 상태는 토글 바로 아래에 설명한다. 첫 실행 플래그는 처리 결과의 의미를 정한 뒤 기록한다.
- 검증: 등록 성공·실패·승인 필요 상태를 확인한다. 이번 검토에서 실제 로그인 항목은 변경하지 않았다.

### P2. 복원 결과 행 수가 카드 전체 높이를 계속 늘림 — 코드 확인, 실기기 판정 필요

- 위치: `App/Plugback/MenuBarCard.swift:143`, `App/Plugback/MenuBarCard.swift:181`.
- 높이 제한은 앱 목록에만 있다. 결과 스트립은 모든 화면의 건너뜀·실패를 제한 없이 나열하고, `이미 제자리`도 개별 행을 만든다. 대상 앱이 많은 정상 복원도 긴 결과 목록이 된다.
- 결과적으로 목록을 제한한 목적과 달리 카드 전체 높이는 계속 커진다. 실제 잘림 여부는 메뉴바 패널과 화면 높이에서 확인해야 한다.
- 최소 수정: 이동·건너뜀·실패 요약은 항상 보이고 사유는 접어서 펼치게 한다. 실패와 현재 필요한 Space 안내는 바로 보이게 유지한다. 펼친 상세에도 높이 제한을 둔다.
- 이는 현재 항상 보이는 사유 표시 정책을 바꾸는 제안이다. 채택하면 US-008·기능 명세·아키텍처 문서를 함께 갱신한다.

## UI 방향: 절제된 macOS 유틸리티

현재 `BRANDING.md`의 시스템 폰트·오렌지·평면 구획을 기준으로 제안한다. 로컬 디자인 검색은 웹 랜딩 위주의 결과라 채택하지 않았으며, 아래는 저장소의 브랜드와 실제 화면 코드를 바탕으로 한 판단이다.

[비교 시안](../prototypes/dropdown-refinement.html)은 브라우저에서 열 수 있는 정적 그림이다. 현재 구성 요약과 제안 구성을 비교하며, 실제 macOS 화면 캡처나 구현 완료 화면은 아니다.

| 영역 | 제안 | 이유 |
| --- | --- | --- |
| 헤더 | 화면 이름과 프로필 상태를 두 줄로 정렬 | 긴 화면 이름과 상태 배지가 가로 공간을 다투지 않게 한다. 여러 외장 화면은 기존 화면별 섹션을 유지한다. |
| 액션 | 프로필이 있으면 복원을 크게, 저장은 보조 액션으로 구분 | 두 긴 버튼이 좁은 폭에서 비슷한 무게로 경쟁하는 문제를 줄인다. 프로필이 없으면 저장을 강조하는 기존 규칙은 유지한다. 버튼은 목록 위에 둔다. |
| 앱 목록 | 일정한 행 높이·체크박스 정렬·Space 제목의 위계 | 장식보다 스캔 속도로 완성도를 높인다. 실행 상태는 글자로도 남긴다. |
| Space 안내 | 해당 Space 안에 출발 → 목적 화면과 다음 행동을 한 덩어리로 표시 | 저장된 소속과 지금 해야 할 일을 구분한다. 일반 비활성 Space에 방문을 요구하지 않는다. |
| 비대상 앱 | 별도 약한 구획, 많을 때 펼쳐 보기 | 복원 대상에 집중하면서도 새 대상 앱을 찾는 경로를 남긴다. 체크 동작의 의미는 바꾸지 않는다. |
| 결과 | 요약을 고정 표시하고 사유 상세는 펼치기 | 평상시 카드 높이를 줄이고 문제 상황은 찾기 쉽게 한다. 실패는 접힌 상태에서도 표시한다. |
| 설정 | 일반·복원 동작·단축키·실험실을 명확히 구분 | 자동 복원과 자동 슬롯의 차이를 더 잘 드러낸다. 아직 설정 수가 적으므로 사이드바는 추가하지 않는다. |

시안의 360px 폭은 비교용 가설이다. 구현에서는 기존 320pt와 나란히 확인한 뒤 결정한다. 앱 아이콘을 넣는 것은 선택 사항이며, 넣더라도 설치된 앱의 실제 아이콘을 사용한다. 별도 그림자·장식용 그라디언트·사용자가 움직일 수 있는 것처럼 보이는 가짜 창 배치도는 추가하지 않는다.

## 적용 순서와 확인 범위

1. 백업 실패와 로그인 상태 피드백을 수정한다.
2. 컨트롤러의 순수 표시 계산을 분리한다. 기존 공개 인터페이스와 정책 테스트를 유지한다.
3. 결과 상세와 목록 View를 분리하면서 카드 시안을 적용한다. 표시 정책이 바뀌는 문서를 함께 수정한다.
4. 실제 메뉴바 패널에서 라이트·다크, 긴 화면 이름, 다중 화면, 앱 20개, 실패 다수, 큰 글자, 키보드·VoiceOver를 확인한다. 저장·복원·권한 없음·연결 해제·Space 이동/방문 안내 상태를 모두 포함한다.

검증 결과: `swift test` **161개 통과, 실패 0개**. 테스트 코드에 동시 실행 클로저의 캡처 변수 변경 경고가 있어 별도 정리가 필요하다. HTML 시안은 Aside에서 다크 모드 렌더링과 결과 상세 펼치기를 확인했다. 앱 호스트 테스트와 실제 창 이동·메뉴바 렌더링은 이번 검토에서 실행하지 않았다. 동시 저장·복원 등 비동기 경계는 기존 `drain` 테스트를 확인했으며, 추가 경쟁 조건을 재현하지 않은 상태에서 결함으로 단정하지 않았다.
