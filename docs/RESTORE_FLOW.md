## A · 이벤트 층 — DisplayWatcher

발화할지 정한다. 여기를 통과하지 못한 케이블은 아래 층이 존재하는지도 모른다.

```
  [화면 파라미터 변경 알림]              [잠금 해제 알림]
   케이블 1회 = 이벤트 3~6회         미뤄둔 회차가 있을 때만 재진입
            │                                  │
            └────────────────┬─────────────────┘
                             ▼
                 디바운스 1.5초 (F-01.2)  ← 이벤트가 올 때마다 다시 시작
                             │
                             ▼
              외장 집합 계산 · 기준선 갱신 ──제거분──▶ 자동 슬롯 확정 (F-08)
                             │                        실험실이 켜졌을 때만
                             ▼
        ◇ 새 식별자 추가 · 또는 미뤄둔 회차?          (F-01.3 위상 게이트)
          └ 아니오 ──▶ 조용히 끝 · 해상도 변경 · 덮개 여닫기 · 평범한 잠금 해제
                             │ 예
                             ▼
        ◇ 화면이 잠겨 있나?                          (F-01.3 잠금 미루기)
          └ 예 ──▶ 미뤄둠 표시 — 버리지 않고 잠금 해제까지 들고 있는다 ──▲ 위로
                             │ 아니오
                             ▼
        ◇ 잠자기 억제 2.5초 안?                      (F-01.3)
          └ 예 ──▶ 이 회차 버림 — 수동 복원으로 잡는다   ※ 미뤄둔 회차는 면제
                             │ 아니오
                             ▼
              ══ onExternalScreensAppeared() ══  감시자의 일은 여기서 끝난다
```

**잠금 판정이 억제 판정보다 위에 있는 이유** — 덮개를 열며 꽂는 흐름은 연결이 곧 잠자기 해제다.
억제를 먼저 보면 그 회차가 버려지고, 기준선은 이미 갱신돼 있어 다시 발화할 길이 없다.

## B · 정책·세션 층 — PlugbackController → RestoreSession

컨트롤러는 실행할지 정하고, 복원 세션은 이번 복원 회차의 범위와 방문 대기를 관리한다. 둘 다 창 API 자체는 모른다.

```
        ◇ 복원 모드가 자동?         (F-05.4)
          └ 수동 ──▶ 복원 버튼을 기다린다 (US-007)
                    │
        ◇ 손쉬운 사용(AX) 권한?     (US-010)
          └ 없음 ──▶ notAuthorized
                    │
        ◇ 외장 화면이 연결됨?
          └ 아님 ──▶ notConnected
                    │
        ◇ 복원이 진행 중이 아님?
          └ 진행 중 ──▶ pendingRestore = true — 끝난 직후 1바퀴 더 돈다
                    ▼
              RestoreSession.restoreAll
                    │
              새 창 열기 → 창 1회 열거
                    │
        ◇ Space 복원 범위가 켜졌나?
          ├ 꺼짐 ──▶ private snapshot 없이 RestoreEngine
          └ 켜짐 ──▶ 일반 Space 사전 재배치 → stable snapshot → RestoreEngine
                       나머지는 방문 대기로 남긴다. Space 방문 때 restoreVisited가
                       안전한 사전 재배치를 다시 시도한 뒤 각 대상을 1회 처리한다.
```

## C · 화면 층 — RestoreEngine, 화면마다

```
        ◇ 그 화면에 프로필이 있나?
          └ 없음 ──▶ 건너뜀 — 결과도 만들지 않는다 (US-007 AC-5)
                    │
        ◇ 저장된 지문 == 현재 지문?  (F-01.4)
          └ 다름 ──▶ 화면 통째로 건너뜀 — 잘못된 복원보다 무작동
                    ▼
              앱 루프 — 그 프로필의 대상 앱
```

## D · 앱 층 — RestoreEngine, 대상 앱마다

일곱 관문을 순서대로 보고 첫 실패에서 멈춘다. 사유는 카드의 점과 결과 스트립이 답한다.
Space binding을 확정하지 못해도 저장 당시의 일반 Space·전체 화면 의도는 남는다. 그 범위가 꺼져 있으면 반대 범위 설정과 무관하게 기존 창 복원 경로를 쓴다(F-08).

```
   체크됨 (US-006) → 실행 중 (F-02.1) → 앞 화면이 안 가져감 (F-01.6)
        → 표준 창 있음 (F-02.2 · 옵션이면 새 창 열기)
        → 전체화면 아님 → 최소화 아님 (옵션이면 Dock에서 꺼냄)
        → 목표와 5pt 초과로 다름 (이미 제자리면 건너뜀)
                    ▼
          이동 → 재판독 검증 → 오차 초과면 간격 없이 즉시 1회 재시도 (F-02.3)
                    │
                    └ 두 번째도 실패 ──▶ 실패로 기록하고 다음 창 — 전체를 멈추지 않는다
```

## 층 요약

| 층 | 모듈 | 정하는 것 | 조건의 출처 |
|---|---|---|---|
| A | DisplayWatcher | 발화할지 | F-01.2 · F-01.3 |
| B | PlugbackController · RestoreSession | 실행할지 · 이번 회차와 방문 대기 | F-05.4 · US-007 · US-010 |
| C | RestoreEngine | 이 화면을 다룰지 | F-01.4 · F-01.6 |
| D | RestoreEngine | 이 창을 옮길지 | F-02.1 · F-02.2 · F-02.3 |

각 층은 아래 층의 조건을 모른다. A가 삼킨 회차는 B가 존재조차 알 수 없고,
C가 건너뛴 화면의 앱은 D에 도달하지 않는다 — 「왜 복원이 안 됐나」는 **위에서부터** 따라 내려가야 한다.
