# Plugback 메뉴바 레이아웃 4종

## 현재 구현 — 2026-09-07 밀도 시안

[새 프로토타입](../prototypes/density-directions.html)을 기준으로 실제 앱의 구성을 바꿨다. 상태 카드를 A로 옮겨 기본값으로 삼고, 빠른 목록을 B로 옮겼다. 모든 레이아웃은 헤더 바로 아래에 복원·저장 버튼을 두고, 그 아래에 실제 복원 소스와 저장 상태를 표시한다. «준비 완료» 같은 별도 상태 박스는 쓰지 않는다.

| 레이아웃 | 구성 | 폭 |
| --- | --- | --- |
| A · 상태 카드 (기본) | 복원·저장 → 저장 상태 → 앱 아이콘·대상 앱 관리. 관리 버튼은 카드 내부의 검색 목록을 연다. | 360pt |
| B · 빠른 목록 | 복원·저장 → 저장 상태 → 검색·촘촘한 앱 목록 | 364pt |
| C · Space 탐색 | 복원·저장 → 화면별 Space 탐색과 선택한 구획의 앱 목록 | 440pt |
| D · 아이콘 보드 | 복원·저장 → 검색·제외 필터 → 네 열의 앱 아이콘 | 400pt |

- 기본 조합은 A + Sage + 시스템 밝기다. 레이아웃·색상·밝기를 독립적으로 저장한다. 기존 설치의 선택값은 유지한다: `comfortable` → 상태 카드, `compact` → 빠른 목록, `command` → Space 탐색, `grouped` → 아이콘 보드.
- 목록의 행은 기본 30pt, 아이콘 20pt, 동작 버튼은 최소 32pt다. 보드는 28pt 아이콘을 쓴다. `CardScrollView`는 오른쪽 스크롤바 여백을 확보하고 높이를 제한한다.
- 검색은 앱 이름과 번들 ID를 찾는다. 제외 앱은 목록에서 기본 접고, 앱을 제외하거나 검색하면 펼친다. 보드의 제외 필터에서는 목록 형태로 재포함·저장 기록 삭제를 제공한다. 저장된 적 없는 앱에는 삭제 동작이 없다.
- C는 실제 저장된 Space만 보여준다. 정보가 없으면 «대상 앱» 목록을 쓴다. 여러 화면의 같은 Space 식별자는 화면 ID와 함께 구분한다. 선택한 화면이나 구획이 사라지면 유효한 첫 항목으로 돌아간다. Space 선택은 목록 탐색이며 복원 범위를 바꾸지 않는다.
- A의 작은 요약 화면에도 복원을 마치기 위한 Space 안내를 표시한다. 저장소 오류·저장 차단·지문 불일치·실패 결과는 실제 컨트롤러 상태를 따른다.
- README의 네 이미지는 실제 SwiftUI 카드를 샘플 프로필(앱 20개·Space 3개)로 렌더링한 것이다. 앱 호스트의 `CardAppearanceTests.testAllLayoutColorCombinationsRenderStoredProfile`이 네 레이아웃 × 네 색상 × 라이트·다크를 렌더링한다. 시스템 임시 디렉터리의 `plugback-{status,list,spaces,board}-dark.png`가 README 이미지의 원본이다.

검증: 코어 테스트 161개, 앱 테스트 20개 통과. 앱 테스트에는 A 관리 화면의 진입·복귀, D 아이콘 클릭으로 실제 프로필 제외, 같은 Space ID를 가진 다중 화면 탐색과 연결 해제 뒤 선택 보정, 긴 목록의 오버레이·일반 스크롤바, 32개 카드 및 설정 화면 렌더가 포함된다. 실제 모니터 재연결·Mission Control 안내 완료·VoiceOver 전수 검증은 이 UI 변경의 자동 검사 범위에 포함하지 않았다.

HTML은 서버 없이 파일을 직접 열어도 동작한다. `?variant=A`~`D`, `apps=8|20`, `theme=light|dark`, `state=ready|guide|failure|offline`, `view=compare`를 지원한다. 실제 저장·창 이동은 하지 않으며 예시 상태만 바꾼다.

## 네 방향의 차이

| 시안 | 구성 | 완성도를 만드는 요소 | 고급스러움의 방향 | 주의할 점 |
| --- | --- | --- | --- | --- |
| A · Graphite | 짧은 헤더 → 고정 액션 → 촘촘한 목록 | 정렬·밀도·짧은 이동 거리 | 그래파이트와 은은한 바이올렛, 절제된 전문 도구 | 익숙하지만 개성은 약하다. |
| B · Porcelain | 큰 제목 → 액션 → 프로필 요약 → 여유 있는 목록 | 명확한 시선 순서·읽기 쉬운 행 | 따뜻한 백색과 블루, 정돈된 Mac 앱 | 네 시안 중 카드가 긴 편이다. |
| C · Command | 화면 식별 → 복원 명령 → 저장 명령 → 대상 목록 | 동작과 설명의 결합·빠른 실행 | 따뜻한 차콜과 코랄, 명령 도구의 정밀함 | 명령 팔레트에 익숙하지 않으면 A/B보다 낯설다. |
| D · Sage | 색 프레임 → 액션 → Space별 내부 구획 | 소속 앱과 안내를 한 덩어리로 읽기 | 세이지와 라일락의 조합, 개성 있는 개인 도구 | 기존 브랜드에서 가장 멀다. 번호·문구 없이 색만으로 상태를 전달하면 안 된다. |

추천은 **B**, 크게 바꾸고 싶다면 **D**다. 이는 시안의 디자인 판단이며 사용자 테스트 점수가 아니다. A의 밀도와 B의 제목·목록 위계를 조합하는 것도 가능하다. 그림자나 채도를 더하는 것보다 정보 위계·상태 피드백·일관된 간격을 먼저 맞추는 편이 완성도에 유리하다.

## 상태와 인터랙션

- 동일한 예시 데이터: 외장 화면 하나, Space 둘, Safari·Slack·Xcode·Linear 네 앱. Linear는 실행 안 됨 상태다.
- 모든 시안에 복원 준비·Space 이동 안내·복원 실패·연결 해제를 넣었다. 실패 안내는 접힌 결과 상세 밖에 남기고, 연결 해제 시 저장·복원 버튼을 비활성화한다.
- 앱 체크·자동 복원 토글은 메모리 안의 예시 상태만 바꾼다. 시안을 바꿔도 선택은 유지한다. 새로고침하면 초기화된다.
- 복원 버튼은 짧은 진행 표시 후 **고정 결과 예시**를 보여준다. 실제 창 이동이나 앱별 정책 계산은 하지 않는다. 선택한 앱 수로 결과를 재계산하는 도메인 시뮬레이터는 아니다.
- 저장·설정·종료는 시안 바깥의 상태 메시지로 범위를 알린다. 실제 설정 창·파일 기록·앱 종료에 연결하지 않는다.
- 시안의 앱 아이콘은 이 Mac에 설치된 해당 앱의 원본 아이콘에서 축소했고 외부 CDN을 요구하지 않는다. 재배포용 브랜드 자산 묶음은 아니다.

## 확인 결과

- Aside에서 4개 구성 × 2개 테마 × 4개 상태, **32개 조합**을 확인했다. 카드 가로 넘침 없음, 모든 조합에 앱 4개 표시, 연결 해제 시 복원 비활성, 안내/실패 상태의 문구 노출을 확인했다.
- 체크박스 변경 후 시안 전환에도 선택이 유지되고, 복원 진행 중 버튼이 비활성화된 뒤 고정 결과 예시가 표시되는 것을 실제 클릭으로 확인했다.
- 375px iframe의 실제 좁은 뷰포트에서 네 시안의 안내 상태를 확인했다. 발견한 그리드 최소 너비 문제를 수정했고 페이지·카드 가로 넘침이 사라졌다.
- 지정 색상 쌍을 계산한 결과, 본문/바탕 최소 **10.93:1**, 보조 글자/보조 표면 최소 **4.51:1**, 강조색/그 위 글자 최소 **5.55:1**이었다. 모든 요소의 접근성 적합성을 인증한 것은 아니다.
- 모션 감소 설정에서 전환을 없애며, 클릭 가능한 요소에 포커스 표시와 이름을 둔다. 키보드·VoiceOver 전수 검증, 다중 외장 화면, 프로필 없음·권한 없음, 시스템 글자 확대, 실제 macOS 패널의 재질·높이는 네이티브 구현 단계에서 확인해야 한다.

제품 소스와 `BRANDING.md`는 변경하지 않았다. 방향을 고른 뒤 필요한 토큰·표현만 제품으로 옮기고, 탈락 시안은 프로토타입 보존 브랜치로 정리한다.
