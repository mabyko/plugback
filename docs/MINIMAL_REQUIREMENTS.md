# 최소요구사항명세서 (Minimal Requirements Specification)

## 프로젝트명: Plugback
**부제: 외장 화면별 창 위치 저장 및 자동 복원 유틸리티**

> 이 문서는 **이 제품이 존재하는 이유**만 담는다. 여기 있는 항목이 하나라도 빠지면 제품이 아니다.
> 세부 동작과 화면 구성은 [FUNCTIONAL_SPEC.md](./FUNCTIONAL_SPEC.md), 용어는 [CONTEXT.md](../CONTEXT.md)를 따른다.

---

## 1. 해결하려는 핵심 문제 (Core Scenario)

```
1. [집] 집 외장 화면에 맥북을 연결하고 앱들의 레이아웃(위치/크기)을 예쁘게 맞춰두고 작업했다.
2. [회사 이동] 회사로 출근해 종류와 해상도가 다른 회사 외장 화면을 연결했다.
3. [회사 작업] 새로운 외장 화면 환경에 맞춰 앱들의 레이아웃을 다시 조절했다.
4. [귀가] 퇴근 후 집에 와서 다시 집 외장 화면을 연결했다.
   🚨 문제 발생: 1번에서 맞춰두었던 집 화면의 앱 레이아웃이 사라지고 엉망이 되어 있다.
```

> **macOS 기본 동작과의 관계**: macOS도 같은 화면을 뺐다 곧 다시 꽂으면 창을 대체로 되돌려 준다.
> 그러나 그 기억은 최근 상태에 묶여 있어서, **사이에 다른 화면을 연결해 배치를 바꾸고 돌아오면
> 이전 화면의 배치는 돌아오지 않는다** (2026-08-16 실기기 관찰). 잠자기·재부팅·앱 재시작을 거치면
> 단순 재연결의 복원도 자주 실패한다. Plugback의 가치가 바로 이 지점이다 — 화면마다 프로필을
> 영구 보관하므로, 언제 어떤 화면으로 돌아와도 그 화면의 배치를 되찾는다.

---

## 2. 필수 핵심 요구사항 (Core Requirements)

### 가. 외장 화면별 독립 프로필 (Per-Screen Independent Profiles)
* 집 화면, 회사 화면 등 연결되는 외장 화면 하드웨어를 고유하게 식별하여, **화면마다 서로 다른 레이아웃을 독립된 프로필로 저장**한다.

### 나. 꺼진 앱 건너뜀 (No Forced Launch)
* 복원할 때 **현재 실행 중이지 않은 대상 앱은 건너뛰며, 강제로 실행하지 않는다.**

### 다. 데려오는 복원, 건드리지 않는 내장 화면 (Non-Intrusive)
* **복원의 기본 원칙: 프로필에 저장된 대상 앱의 창은 지금 어느 화면에 있든 외장 화면의 제자리로 데려온다.** 건너뛰는 이유는 앱이 꺼져 있는 것(요구사항 나), 특수 창 상태(3장), 표준 창이 하나도 없는 것(설정으로 예외 가능), 이미 제자리인 것뿐이다. 케이블을 뽑으면 macOS가 창을 내장 화면으로 옮겨두므로, 데려오지 못하면 핵심 시나리오가 성립하지 않는다.
* **내장 화면의 배치는 저장하지 않고, 내장 화면의 작업 공간은 재배치하지 않는다.** 프로필에 없는 앱의 창은 어디에 있든 불변이다.
* 창 선택: 대상 앱이 외장 화면에 이미 창을 갖고 있으면 그 창을 옮긴다. 그 경우 내장 화면에 있는 같은 앱의 다른 창은 건드리지 않는다.

### 라. 레이아웃 수동 저장 (Manual Capture)
* 외장 화면의 레이아웃은 사용자가 메뉴바에서 `[💾 지금 레이아웃 저장]`을 누를 때만 저장한다. 백그라운드 자동 저장은 하지 않는다.
* **병합 규칙**: 저장은 지금 외장 화면에 창이 있는 앱의 항목만 갱신한다. 프로필에 등록되어 있으나 지금 실행 중이 아닌 앱의 항목은 **그대로 유지**한다.
  * 예: 집 프로필에 Chrome·VSCode·Slack이 있고 오늘 Slack을 켜지 않았다면, 저장해도 Slack 항목은 남는다.
* 프로필에서 앱을 빼는 것은 사용자가 명시적으로 삭제할 때만 일어난다.

### 마. 외장 화면 연결 시 자동 복원 (Auto-Restore on Connect)
* 외장 화면이 연결되면 해당 화면의 프로필대로 **대상 앱의 창을 자동으로 복원**한다.
* 자동 복원이 안전한 이유는 **선택 복원**이기 때문이다. 대상 앱 외에는 아무것도 건드리지 않으므로 사용자에게 확인을 받을 필요가 없다.

## 3. 세부 동작 엣지케이스 규칙 (Behavioral Rules)

1. **동일 앱 다중 창 처리**:
   * 같은 앱(예: Chrome)의 창이 내장 화면과 외장 화면에 각각 떠 있으면, **외장 화면에 있던 창만** 저장하고 복원한다. 내장 화면의 창은 건드리지 않는다.
   * 앱이 계속 실행 중인 동안에는 그 창을 정확히 추적한다. **창 동일성은 보장하지 않는다 — 복원할 때마다 규칙(대상 화면의 창 우선, 없으면 이동 가능한 표준 창)으로 다시 고른다.**
2. **해상도/배율 독립성 (비율 좌표)**:
   * 픽셀 절대 좌표가 아닌 화면 대비 비율(좌측 50%, 우측 50% 등)로 저장하여, 해상도나 배율이 바뀌어도 깨지지 않고 복원한다.
3. **특수 창 안전 건너뜀**:
   * 네이티브 전체화면 창과 Dock에 최소화된 창은 복원 시 건너뛴다. (최소화는 설정 「최소화된 창도 복원」으로, 창 없음은 「창이 없는 앱은 새 창을 열어 복원」으로 예외 가능 — 둘 다 기본 꺼짐이며, 어느 쪽도 꺼진 앱을 실행하지는 않는다)
   * 팝업·패널·툴팁 등 보조 창은 저장·복원 대상이 아니다.

---

## 4. 명확한 비목표 (Non-Goals / 하지 않는 것)

* 화면을 좌우/상하로 쪼개는 단순 창 분할(타일링/스냅) 기능은 만들지 않는다.
* 내장 화면을 포함한 **전체 스냅샷** 덮어쓰기는 절대 하지 않는다.
* '화면 기록(Screen Recording)' 권한을 요구하지 않고 오직 '손쉬운 사용(Accessibility)' 권한으로만 동작한다.
* 백그라운드 자동 저장은 하지 않는다. 저장 시점은 항상 사용자가 결정한다.
* 외장 화면이 분리될 때는 아무 동작도 하지 않는다.
