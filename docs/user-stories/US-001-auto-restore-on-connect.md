# US-001 · 외장 화면을 연결하면 창이 제자리로 돌아온다

**우선순위:** P0 · **관련:** 요구사항 마 / F-01, F-02

## 스토리

> **도킹 사용자로서**, 외장 화면 케이블을 꽂기만 하면 대상 앱들이 저장해둔 자리로 알아서 돌아갔으면 좋겠다.
> **그래야** 자리에 앉을 때마다 창을 다시 배치하지 않는다.

## 인수 조건

**AC-1 · 기본 복원**
- **Given** 집 작업 환경 저장본에 Chrome 창 둘(좌·우 각각)과 VSCode(가운데)가 저장되어 있고, 두 앱이 실행 중이다
- **When** 집 외장 화면을 연결한다
- **Then** Chrome 창 둘은 각자 저장한 자리로, VSCode는 가운데로 놓인다 — 같은 앱이라고 하나만 옮기지 않는다
- **And** 복원은 한 번만 일어난다. 창이 여러 번 움직이지 않는다

**AC-2 · 신호 안정화**
- **Given** 케이블을 꽂는 동안 화면 해상도가 여러 번 바뀐다
- **When** 화면 구성이 최종 확정된다
- **Then** 확정된 크기를 기준으로 복원한다. 중간 크기 기준으로 잘못 배치되지 않는다

**AC-3 · 저장본 없는 조합**
- **Given** 처음 보는 외장 화면이거나, 아는 화면이지만 처음 보는 조합(A 단독은 있고 A+B는 없음)이다
- **When** 그 조합을 연결한다
- **Then** 아무 창도 움직이지 않는다. 다른 조합의 저장본을 대신 쓰지 않는다
- **And** 메뉴바에서 이 조합에 저장본이 없다는 것을 알 수 있다

**AC-4 · 해상도가 바뀐 경우**
- **Given** 저장할 때와 다른 해상도로 같은 화면을 연결했다
- **When** 복원이 실행된다
- **Then** 저장된 비율 그대로 배치된다. 우측 50%는 여전히 우측 50%다

**AC-5 · 저장한 Space가 다른 화면에 남은 경우**
- **Given** 외장 화면에 저장한 일반 Space가 내장 화면에 남아 있다
- **When** 연결 복원이 시작된다
- **Then** Plugback은 출발·목적 화면을 알려주고 Space를 직접 옮기지 않는다
- **When** 사용자가 Mission Control에서 그 Space를 외장 화면으로 옮기고 한 번 연다
- **Then** 버튼을 다시 누르지 않아도 그 Space의 대상 표준 창만 저장 위치로 복원된다

**AC-6 · 비활성 Space는 요청 안에서만 방문 대기**
- **Given** 저장한 일반 Space가 외장 화면에 있지만 현재 비활성이다
- **When** 연결 복원이 시작된다
- **Then** 그 Space의 창은 「방문 대기」로 남고, 카드에 화면 이름과 함께 보인다
- **When** 그 Space를 한 번 연다
- **Then** 남은 창만 저장 위치로 복원되고 요청이 끝난다. 시간이 오래 지나도 대기는 만료되지 않는다
- **And** 요청이 끝난 뒤의 평소 방문에는 창을 움직이지 않는다

**AC-7 · 순차 연결**
- **Given** 독을 통해 A가 먼저, B가 나중에 나타난다
- **When** A만 안정되면 A 단독 저장본으로 복원하고, B가 추가되면 A의 남은 작업을 중단하고 A+B 저장본으로 다시 복원한다
- **And** 그사이 사용자가 직접 옮기고 있던 창은 이번 자동 복원에서 건너뛴다

## 비고

자동 복원을 사용자 확인 없이 실행해도 되는 이유는 **선택 복원**이기 때문이다.
대상 앱 외에는 아무것도 건드리지 않으므로 되돌릴 것이 없다. → US-005
