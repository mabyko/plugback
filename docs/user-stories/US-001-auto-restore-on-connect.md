# US-001 · 외장 화면을 연결하면 창이 제자리로 돌아온다

**우선순위:** P0 · **관련:** 요구사항 마 / F-01, F-02, F-08.5

## 스토리

> **도킹 사용자로서**, 외장 화면 케이블을 꽂기만 하면 대상 앱들이 저장해둔 자리로 알아서 돌아갔으면 좋겠다.
> **그래야** 자리에 앉을 때마다 창을 다시 배치하지 않는다.

## 인수 조건

**AC-1 · 기본 복원**
- **Given** 집 화면 프로필에 Chrome(우측 50%)과 VSCode(좌측 50%)가 저장되어 있고, 두 앱이 실행 중이다
- **When** 집 외장 화면을 연결한다
- **Then** Chrome은 우측 절반, VSCode는 좌측 절반에 놓인다
- **And** 복원은 한 번만 일어난다. 창이 여러 번 움직이지 않는다

**AC-2 · 신호 안정화**
- **Given** 케이블을 꽂는 동안 화면 해상도가 여러 번 바뀐다
- **When** 화면 구성이 최종 확정된다
- **Then** 확정된 크기를 기준으로 복원한다. 중간 크기 기준으로 잘못 배치되지 않는다

**AC-3 · 프로필 없는 화면**
- **Given** 처음 보는 외장 화면이다
- **When** 그 화면을 연결한다
- **Then** 아무 창도 움직이지 않는다
- **And** 메뉴바에서 이 화면에 프로필이 없다는 것을 알 수 있다

**AC-4 · 해상도가 바뀐 경우**
- **Given** 저장할 때와 다른 해상도로 같은 화면을 연결했다
- **When** 복원이 실행된다
- **Then** 저장된 비율 그대로 배치된다. 우측 50%는 여전히 우측 50%다

**AC-5 · 저장한 Space가 다른 화면에 남은 경우**
- **Given** 외장 화면에 저장한 일반 Space가 내장 화면에 남아 있다
- **When** 연결 복원이 시작된다
- **Then** Plugback은 출발·목적 화면을 알려주고 Space를 직접 옮기지 않는다
- **When** 사용자가 Mission Control에서 그 Space를 외장 화면으로 옮기고 한 번 연다
- **Then** 버튼을 다시 누르지 않아도 그 Space의 대상 표준 창만 저장 위치로 복원된다

**AC-6 · 평소 Space 방문은 복원 트리거가 아님**
- **Given** 저장한 일반 Space가 처음부터 외장 화면에 있지만 현재 비활성이다
- **When** 연결 복원 뒤 그 Space를 방문한다
- **Then** 방문했다는 이유만으로 창 위치를 다시 덮어쓰지 않는다

## 비고

자동 복원을 사용자 확인 없이 실행해도 되는 이유는 **선택 복원**이기 때문이다.
대상 앱 외에는 아무것도 건드리지 않으므로 되돌릴 것이 없다. → US-005
