# US-008 · 왜 안 옮겨졌는지 확인한다

**우선순위:** P1 · **관련:** F-02.3, F-05.1

## 스토리

> **도킹 사용자로서**, 어떤 앱이 제자리로 가지 않았을 때 그 이유를 알고 싶다.
> **그래야** 앱이 고장 난 건지, 내가 뭔가 잘못한 건지 판단할 수 있다.

## 인수 조건

**AC-1 · 결과 요약**
- **Given** 복원이 방금 끝났다
- **When** 메뉴바를 연다
- **Then** `이동 2 · 건너뜀 1 · 대기 1 · 확인 필요 1 · 실패 0` 형식으로 결과가 보인다. 대기·확인 필요·취소는 있을 때만 붙는다
- **And** 펼치면 저장 창마다 한 줄이 있다 — 같은 앱의 창 둘은 두 줄이다

**AC-6 · 창 확인 필요**
- **Given** 저장한 창을 현재 확인할 수 없거나 같은 앱의 후보를 구별할 수 없다
- **When** 카드의 「창 확인 필요 N개」를 누른다
- **Then** 「복원 확인」 창에서 앱·화면 이름·Space 번호·저장 위치·사유를 항목마다 볼 수 있다. 창은 자동으로 뜨지 않는다
- **And** 「남은 창 복원」을 눌러야 다시 판정한다. 창을 나중에 발견해도 저절로 옮기지 않는다

**AC-2 · 건너뛴 이유**
- **Given** Chrome이 전체화면이라 건너뛰었다
- **When** 결과를 확인한다
- **Then** Chrome이 건너뛰어졌다는 것과 그 이유(전체화면)를 알 수 있다
- **And** 이유는 사용자가 이해할 수 있는 말로 표시된다

**AC-3 · 실패 감지**
- **Given** 창을 옮겼지만 앱의 최소 크기 제약 때문에 요청한 크기가 되지 않았다
- **When** 복원이 끝난다
- **Then** 앱이 한 번 더 시도한다
- **And** 그래도 안 되면 **실패로 기록된다.** 성공한 것처럼 보고하지 않는다

**AC-4 · 부분 실패에도 계속 진행**
- **Given** 대상 앱 4개 중 하나가 실패한다
- **When** 복원이 실행된다
- **Then** 나머지 3개는 정상적으로 복원된다. 전체가 중단되지 않는다

**AC-5 · 아무 일도 안 일어났을 때**
- **Given** 화면을 연결했는데 아무 창도 움직이지 않았다
- **When** 메뉴바를 연다
- **Then** 이유를 알 수 있다 — 저장본 없음(헤더) / 대상 앱의 체크 상태·「꺼짐」 표시와 실제 복원 결과(목록·결과 스트립) / 수동 복원 모드(푸터의 자동 복원 스위치 꺼짐) / 권한 없음(온보딩 화면으로 교체) / 화면 정보가 저장 당시와 다름(지문 불일치 경고) / 개별 Spaces 설정 꺼짐(안내 배너) / 잠금 상태를 확인하지 못해 대기(대기 줄)

## 비고

AC-5가 이 카드의 핵심이다. **아무 일도 일어나지 않는 것**이 이 제품의 가장 흔한 실패 모습이고,
그때 사용자가 볼 수 있는 곳이 여기 하나뿐이다. 이게 없으면 문의가 전부 "안 돼요"로 온다.
