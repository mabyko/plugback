# US-004 · 꺼둔 앱이 멋대로 켜지지 않는다

**우선순위:** P0 · **관련:** 요구사항 나 / F-02.1, F-02.2

## 스토리

> **도킹 사용자로서**, 화면을 연결했을 때 지금 꺼둔 앱이 저절로 실행되지 않았으면 좋겠다.
> **그래야** 집중하려고 닫아둔 Slack이 퇴근 후 화면을 꽂자마자 다시 튀어나오지 않는다.

## 인수 조건

**AC-1 · 꺼진 앱은 건너뛴다 (기본값)**
- **Given** 집 저장본에 Chrome·VSCode·Slack이 있고, Slack은 종료된 상태다
- **When** 집 화면을 연결한다
- **Then** Chrome과 VSCode만 복원된다
- **And** **Slack은 실행되지 않는다** — 실험실 「종료된 앱 다시 열기」는 최초 꺼짐이다
- **And** 오류 메시지나 경고창이 뜨지 않는다

**AC-2 · 프로필 항목은 유지된다**
- **Given** AC-1 직후다
- **When** Slack을 직접 실행한 뒤 `[↶ 지금 복원]`을 누른다
- **Then** Slack도 저장된 자리로 이동한다. 프로필에서 지워지지 않았다

**AC-3 · 전체화면 창은 건드리지 않는다**
- **Given** Chrome이 네이티브 전체화면 상태다
- **When** 화면을 연결해 복원이 실행된다
- **Then** Chrome은 전체화면 그대로 남는다. 전체화면이 해제되지 않는다
- **And** 건너뛴 이유를 메뉴바에서 확인할 수 있다 → US-008

**AC-4 · 최소화된 창은 건드리지 않는다 (기본값)**
- **Given** VSCode 창이 Dock에 최소화되어 있다
- **When** 복원이 실행된다
- **Then** 창은 최소화 상태로 남는다. 저절로 복구되지 않는다
- **단** 설정 「최소화된 창도 복원」(기본 꺼짐)을 켜면 Dock에서 꺼내 저장된 자리로 옮긴다

**AC-5 · 응답 없는 앱**
- **Given** 대상 앱 하나가 응답하지 않는다
- **When** 복원이 실행된다
- **Then** 메뉴바가 멈추지 않는다
- **And** 나머지 앱은 정상적으로 복원된다

**AC-6 · 실행 중인데 창이 없는 앱 (기본값: 건너뜀)**
- **Given** Fork가 실행 중이지만 표준 창을 모두 닫아 뒀다
- **When** 복원이 실행된다
- **Then** 건너뛰고, 이유(창이 없어 건너뜀)를 확인할 수 있다 → US-008

**AC-7 · 실험실 「종료된 앱 다시 열기」**
- **Given** 회사 저장본에 Aside·Slack이 있고, 집에서 Slack을 종료했다 (Plugback이 그 종료를 관찰했다)
- **When** 회사 화면으로 돌아와 복원되고, 실험실 「종료된 앱 다시 열기」가 켜져 있다
- **Then** Slack을 실행(포커스 없이)한 뒤 창이 나타나면 저장한 자리로 옮긴다. Aside 창의 배치도 계속 복원한다
- **And** 「실행 중인 앱 창 되살리기」가 켜져 있어야 창 0개인 앱에 기본 창을 열고, 「부족한 창 추가로 열기」가 켜져 있어야 부족한 창을 더 연다. 자식 옵션은 부모가 꺼져 있으면 동작하지 않는다
- **And** 회사에서 직접 닫은 창의 자리는 다음 저장까지 채우지 않는다. Plugback이 꺼진 사이 닫혀 언제 닫혔는지 모르는 창은 열지 않고 「창 확인 필요」에 사유를 보여준다
- **And** 탭·문서 내용은 복구하지 않는다
