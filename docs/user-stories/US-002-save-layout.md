# US-002 · 지금 배치를 이 작업 환경의 저장본으로 저장한다

**우선순위:** P0 · **관련:** 요구사항 라 / F-03

## 스토리

> **도킹 사용자로서**, 창을 마음에 들게 배치한 뒤 버튼 하나로 그 배치를 이 화면 조합의 저장본으로 저장하고 싶다. 저장을 잊어도 떠날 때 저장됐으면 좋겠다.
> **그래야** 다음에 같은 조합을 연결했을 때 같은 배치를 되찾는다.

## 인수 조건

**AC-1 · 저장**
- **Given** 외장 화면에 Chrome과 VSCode를 배치해두었다
- **When** 메뉴바에서 `[💾 지금 레이아웃 저장]`을 누른다
- **Then** 두 앱의 창 각각의 위치가 이 작업 환경의 저장본에 저장된다. 같은 앱의 창이 둘이면 둘 다 기록된다
- **And** 저장됐다는 것을 화면에서 확인할 수 있다 — 일회성 확인 표시이며, 카드를 다시 열면 사라진다. 저장이 실제로 되지 않았다면(권한 없음·저장소 문제·Space 관찰 실패) 성공 표시는 나오지 않는다
- **And** 파일 쓰기가 실패하면 이전 프로필과 저장 대기 후보를 그대로 두고 알리며, 다음 저장에서 다시 시도할 수 있다
- **And** Space 상태를 확실히 확인하지 못하면 기존 프로필·Space 정보·저장 대기 후보를 그대로 두고 저장하지 않았다고 알리며, 다음 저장 버튼에서 다시 시도한다

**AC-2 · 내장 화면 창은 저장하지 않는다**
- **Given** Slack이 내장 화면에 떠 있다
- **When** 저장을 누른다
- **Then** Slack은 프로필에 들어가지 않는다

**AC-3 · 걸친 창**
- **Given** 창 하나가 두 화면에 걸쳐 있다
- **When** 저장을 누른다
- **Then** 창의 **중심점**이 있는 화면에 속한 것으로 저장된다

**AC-4 · 병합 — 꺼둔 앱이 사라지지 않는다**
- **Given** 집 저장본에 Chrome·VSCode·Slack이 있고, 오늘은 Slack을 켜지 않았다
- **When** 저장을 누른다
- **Then** Chrome과 VSCode의 창 위치는 갱신된다
- **And** **Slack 기록은 저장본에 그대로 남는다**
- **And** 다음에 Slack을 켜고 이 조합을 연결하면 Slack도 복원된다

**AC-7 · 외장 화면에 나타난 앱은 기본 포함, 제외한 앱만 뺀다**
- **Given** 저장본에 Chrome·VSCode가 있고, 새로 연 Keynote 창이 외장 화면에 있다
- **When** 저장을 누른다
- **Then** Keynote도 새 창 위치 기록으로 들어간다 — 처음 저장이든 이후 저장이든 같다
- **And** 카드에서 체크를 끈 앱만 저장·복원에서 빠진다. 그 앱의 기존 기록은 남아 다시 켜면 그 자리로 돌아온다

**AC-5 · 작업 중 이력은 복원 기준이 아니다**
- **Given** 외장 화면에서 창을 여기저기 옮기며 작업한다
- **When** 저장 버튼을 누르지 않고 「지금 복원」을 누른다
- **Then** **마지막으로 저장이 완료된 배치**로 돌아간다. 작업 중 이력은 카드에 「저장 대기」로만 보인다

**AC-6 · 환경을 떠날 때 자동 저장**
- **Given** 자동 저장이 켜져 있다(최초 켜짐)
- **When** 케이블을 뽑거나 화면을 추가해 작업 환경을 떠난다, 또는 Plugback을 종료한다
- **Then** 떠나는 환경의 마지막 유효 배치가 저장되고, 다음 복원은 그 배치를 쓴다. 저장할 변경이 없으면 저장하지 않는다
- **And** 자동 저장을 끄면 저장 대기 이력을 버리고 마지막 저장본은 그대로 둔다. 다시 켜도 그것만으로 저장되지 않는다
- **And** 종료 전 저장이 실패하면 종료를 취소하고 다시 시도하거나 저장하지 않고 종료할지 묻는다

**AC-8 · 같은 창의 이동과 새 창 추가를 구별한다**
- **Given** A 화면에 저장한 Keynote 창을 B 화면으로 옮겼다
- **When** 저장하거나 자동 저장이 완료된다
- **Then** 그 창의 기록은 B로 갱신되고 A의 옛 자리는 남지 않는다. A에 두고 B에 새 창을 열었다면 둘 다 기록된다

## 비고

AC-5·AC-6이 이 카드의 핵심이다. 자동 저장을 기본으로 켜되 **작업 중 이력이 복원 기준을 바꾸지 않고**, 환경을 떠날 때와 종료 전에만 저장이 완료된다. 복원 직후의 착지 위치는 사용자가 그 창을 옮기기 전까지 이력으로 승격하지 않으므로, 부분 실패가 저장본을 덮어쓰지 않는다.

그 근거는 지금도 유효하다. 바뀐 것은 **자동 저장이 원본을 덮어써야 한다는 전제**다.
슬롯을 나누면 자동은 자기 슬롯에만 쓰고, 사람이 저장한 배치는 그대로 남는다 —
사고의 원인이 "자동 저장"이 아니라 "한 칸에 둘이 쓰는 것"이었다.

AC-6이 뒤따르는 이유: 슬롯이 둘이면 "저장했는데 왜 안 돌아와?"가 새로 생긴다.
더 최근 것이 이기는 규칙 하나가 그것을 막고, 슬롯 전환 조작을 없앤다
(검증: FUNCTIONAL_SPEC F-08.2, `LabAutoSlotTests.testManualSaveBecomesTheNewestSource`).
