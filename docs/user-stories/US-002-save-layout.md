# US-002 · 지금 배치를 이 화면의 프로필로 저장한다

**우선순위:** P0 · **관련:** 요구사항 라 / F-03

## 스토리

> **도킹 사용자로서**, 창을 마음에 들게 배치한 뒤 버튼 하나로 그 배치를 이 화면의 프로필로 저장하고 싶다.
> **그래야** 다음에 이 화면을 연결했을 때 같은 배치를 되찾는다.

## 인수 조건

**AC-1 · 저장**
- **Given** 외장 화면에 Chrome과 VSCode를 배치해두었다
- **When** 메뉴바에서 `[💾 지금 레이아웃 저장]`을 누른다
- **Then** 두 앱의 위치가 이 화면의 프로필에 저장된다
- **And** 저장됐다는 것을 화면에서 확인할 수 있다 — 일회성 확인 표시이며, 카드를 다시 열면 사라진다. 저장이 실제로 되지 않았다면(권한 없음·저장소 문제·Space 관찰 실패) 성공 표시는 나오지 않는다
- **And** 파일 쓰기가 실패하면 이전 프로필과 저장 대기 후보를 그대로 두고 알리며, 다음 저장에서 다시 시도할 수 있다
- **And** Space 상태를 확실히 확인하지 못하면 기존 프로필·Space 정보·저장 대기 후보를 그대로 두고 저장하지 않았다고 알리며, 다음 저장 버튼에서 다시 시도한다

**AC-2 · 내장 화면 창은 저장하지 않는다**
- **Given** Slack이 내장 화면에 떠 있다
- **When** 저장을 누른다
- **Then** Slack은 프로필에 들어가지 않는다

**AC-3 · 걸친 창**
- **Given** 창 하나가 두 화면에 걸쳐 있다
- **When** 저장을 누른다
- **Then** 창의 **중심점**이 있는 화면에 속한 것으로 저장된다

**AC-4 · 병합 — 꺼둔 앱이 사라지지 않는다**
- **Given** 집 프로필에 Chrome·VSCode·Slack이 등록되어 있고, 오늘은 Slack을 켜지 않았다
- **When** 저장을 누른다
- **Then** Chrome과 VSCode의 위치는 갱신된다
- **And** **Slack 항목은 프로필에 그대로 남는다**
- **And** 다음에 Slack을 켜고 이 화면을 연결하면 Slack도 복원된다

**AC-5 · 내가 저장한 것은 나만 바꾼다**
- **Given** 외장 화면에서 창을 여기저기 옮기며 작업한다
- **When** 저장 버튼을 누르지 않는다
- **Then** **내가 저장했던 배치는 변하지 않는다**
- **And** 케이블을 뽑아도 변하지 않는다
- **And** 실험실 · 자동 슬롯을 켰더라도 변하지 않는다 — 자동 저장은 **별도 슬롯**에만 쓴다

**AC-6 · 저장하면 그 배치가 쓰인다**
- **Given** 실험실 · 자동 슬롯이 켜져 있고, 자동 슬롯이 복원에 쓰이고 있다
- **When** 창을 배치하고 저장을 누른다
- **Then** 다음 복원은 방금 저장한 배치를 쓴다 — 더 최근에 저장된 쪽이 이기기 때문이다
- **And** 슬롯을 고르는 별도 조작이 없다. 카드에 어느 쪽이 쓰이는지 보인다

## 비고

AC-5가 이 카드의 핵심이다. 원래 문장은 "자동 저장 없음"이었고, 근거는
**자동 저장이 복원의 부분 실패 상태를 덮어써서 원본을 잃게 만든다**는 것이었다.

그 근거는 지금도 유효하다. 바뀐 것은 **자동 저장이 원본을 덮어써야 한다는 전제**다.
슬롯을 나누면 자동은 자기 슬롯에만 쓰고, 사람이 저장한 배치는 그대로 남는다 —
사고의 원인이 "자동 저장"이 아니라 "한 칸에 둘이 쓰는 것"이었다.

AC-6이 뒤따르는 이유: 슬롯이 둘이면 "저장했는데 왜 안 돌아와?"가 새로 생긴다.
더 최근 것이 이기는 규칙 하나가 그것을 막고, 슬롯 전환 조작을 없앤다
(검증: FUNCTIONAL_SPEC F-08.2, `LabAutoSlotTests.testManualSaveBecomesTheNewestSource`).
