# Space별 창 저장·복원 구현 인계

2026-09-11 · 현재 워크트리 `runner` · 출발 코드 `09f9d67`

사용자는 설계 논의를 마무리하고 구현으로 넘어가는 데 동의했으며, **Orca로 현재 워크트리에 이미 열려 있는 Claude 세션을 찾아 실제 구현을 요청하도록 지정했다.** 이 문서는 그 세션에 전달하는 작업 지시다. Codex는 설계 문서와 인계만 정리했고 제품 코드는 수정하지 않았다.

## 목표와 기준

외장 화면 조합마다 독립된 작업 환경을 두고, 일반 Space 안의 표준 창을 각각 저장·복원한다. 같은 앱의 창이 여러 개여도 개별 기록과 결과를 제공한다. 합의한 저장 시점·창 대응·요청 수명·실험실 설정·화면 표시까지 제품에 연결하고, 회귀 검사와 문서를 함께 갱신한다. 계획이나 독립된 새 모델 파일만 만든 상태로 완료하지 않는다.

다음 순서로 읽는다.

1. [Space 상태 검토](./SPACE_LAYOUT_STATE_REVIEW.md): 1절 모델, 3–4절 동작, 5절 162개 상태 사례, 6절 우선순위, 7절 합의와 **7.1절 남은 세 묶음의 구현 기본안**, 8절 근거·검증 계획.
2. [제품 설계 검토](./PRODUCT_DESIGN_REVIEW.md): 현재 코드의 R1–R6 문제와 수정 이유.
3. [CONTEXT](../CONTEXT.md), [기능 명세](./FUNCTIONAL_SPEC.md), [아키텍처](./ARCHITECTURE.md), [비공식 API 목록](./UNDOCUMENTED_APIS.md), [빌드 절차](./BUILD_RUNBOOK.md).

새 합의와 기존 구현 문서가 충돌하면 이번 사용자 합의를 따른다. 기존의 「앱당 좌표 하나」「종료 앱 실행 금지」「처음부터 비활성인 Space는 복원하지 않음」「자동 슬롯 즉시 확정」「Space 연결은 메모리에서만 보존」을 새 동작의 제약으로 유지하지 않는다. 실제 코드 변경과 함께 관련 문서·테스트를 갱신한다. 근거 없이 사용자 합의를 다시 열거나 구현 편의를 위해 범위를 줄이지 않는다.

## 반드시 지킬 동작

- **작업 환경:** 외장 A+B와 A 단독은 별도 저장본이다. 내장은 조합에 넣지 않는다. 다른 환경의 일부 기록을 대신 골라 복원하지 않는다. 포트·표시 이름·A/B 문자만 바뀌었다고 새 환경으로 만들지 않는다.
- **창별 기록:** 같은 Space의 같은 앱 창도 각각 위치·크기를 저장한다. 앱은 포함·제외 단위이며 최초·이후 새로 외장에 나타난 표준 창을 기본 포함한다. 같은 실제 창의 화면 이동과 새 창 추가를 구별한다. 탭·문서 내용 복구는 후속 범위다.
- **저장:** 일반 자동 저장은 최초 ON, 명시적 선택 유지. 수집한 것은 저장 대기 이력이며 수동 저장·환경 이탈·정상 종료 전 성공한 저장으로 확정한다. 모든 복원은 수동·자동 구분 없이 해당 환경의 마지막 저장 완료본을 사용하고 한 요청의 소스를 고정한다. 복원 중간·실패 배치를 새 기준으로 삼지 않는다. 새 수동 저장 뒤 늦은 관찰이 이를 덮지 않게 한다.
- **저장 실패:** 원본·마지막 저장본·유효 이력 유지. 정상 종료 전 저장 실패는 종료를 취소하고 재시도·저장 없이 종료를 제공한다. 실제 종료·비정상 종료 뒤에는 마지막 저장 완료본만 복원한다.
- **현재 창 대응:** 확인된 유효 연결을 먼저 재사용한다. 모호한 후보는 전체 이동 거리를 최소화하는 일대일 배정, 동률이면 크기 차이·일정한 순서를 사용한다. 필요한 후보만 고르고 남는 창은 유지한다. 추정 배정을 과거 창의 정확한 식별로 취급하지 않는다. 같은 실제 창·저장 자리 확인이 깨지면 옛 참조를 버린다.
- **직접 지정:** 실험실 최초 OFF. ON이면 모호한 후보를 사용자가 지정할 수 있다. ON/OFF 전환은 팝업·복원 시작·재개를 일으키지 않는다. 유효한 확정 연결·완료 배치는 유지하고 OFF 때 미확정 선택만 취소한다. 취소된 선택과 늦은 응답은 다시 ON으로 켜도 되살리지 않는다.
- **닫힌 창:** 같은 환경에서 닫힌 것으로 확인한 기록은 해당 환경의 다음 저장 성공까지 제외한다. 시간·재연결·Plugback 재실행으로 제외를 풀지 않는다. 다른 환경에서 닫힌 원래 기록은 유지한다. 닫힌 시점·환경이 불확실하면 기록·사유를 남기고 해당 앱 실행·창 생성을 보류한다. 사용자가 직접 연 창은 「남은 창 복원」에서 다시 판정한다.
- **실험실:** 모든 ON/OFF는 선택 이력이 없으면 OFF. 부모 「종료된 앱 다시 열기」, 자식 「실행 중인 앱 창 되살리기」(실제 0→기본 창)·「부족한 창 추가로 열기」(이미 1개 이상→부족분)를 구별한다. 부모 OFF는 명시적 실행·생성 전체를 막고 기존 창 배치는 허용한다. 추가 열기 ON으로 되살리기 OFF를 우회하지 않는다. 관찰 실패·다른 Space·최소화를 창 0개로 세지 않는다. 실행·생성 직전 최신 설정을 확인하고 이미 요청한 창을 강제로 닫지 않는다.
- **요청 수명:** 확인 필요는 사용자 「남은 창 복원」으로만 재개한다. 단순 Space 방문 대기·이동 안내는 유효한 동안 이벤트를 기다리며 임의 만료·대기용 반복 타이머를 두지 않는다. 취소·새 요청·새 저장·환경 변경·대상 무효화·실제 종료에 따라 옛 요청을 정리한다. 자동 복원 OFF는 자동 요청의 미처리 부분만 취소하고 사용자 요청은 유지한다. 다시 ON이나 Plugback 재실행만으로 즉시 복원하지 않는다.
- **잠금·사용자 조작:** 잠금 중 미전송 조작을 중단한다. 해제 후 같은 환경의 여전히 유효한 남은 항목만 고정한 소스로 재개한다. 판정 불가는 보류·사유 표시다. 단축어는 실행 전 잠금 해제를 요구하며 별도 예약 기능을 추가하지 않는다. 연결 때 짧게 재확인해 준비된 조합부터 복원하고, 사용자가 조작한 창은 그 자동 복원에서 보호한다. 정확한 신호·대기 시간은 실측한다.
- **Spaces 지원:** 첫 구현은 「각각의 Spaces가 있는 디스플레이」 ON 구성이다. OFF·판정 불가에서는 새 Space 저장·복원을 보류하고 기록·지원 안내를 유지한다. Space 제약을 지운 위치 복원으로 몰래 전환하지 않는다. 지원 조건 변경 시 기존 요청 처리는 상태 검토 7.1절을 따른다.
- **표시:** 모니터 이름+맥 본체 포트 위치 우선, 위치 불명·공유 포트의 중복은 A/B로 구분한다. 예: `LG Fine 24 (왼쪽 위)` / `LG Fine 24 (오른쪽 · A)`. 화면별 일반 Space만 순서대로 Space 1, 2, …를 붙이고 전체화면·Split View를 제외한다. macOS 데스크탑 번호에 맞추지 않는다. 포트·문자·Space 표시 번호는 영구 식별 키가 아니다.
- **확인 UI·진단·이전:** 상태 검토 7.1절의 기본안을 적용한다. 제목·URL·내용·화면 캡처·세션 사전 원문을 진단 기록에 넣지 않는다. 자동 원격 전송은 없다. 구버전의 선택·프로필 원본을 보존하고 없는 조합·Space 정보를 만들어 내지 않는다.

## 구현 순서와 소유 범위

이 워크트리의 제품 구현은 수신한 Claude 세션이 맡는다. 새 워크트리나 중복 Claude 세션을 만들 필요가 없다. Codex가 작성한 기존 변경·미추적 파일을 보존하고 전체 리셋·덮어쓰기를 하지 않는다. 필요한 제품 코드·검사·관련 문서는 수정할 수 있다.

1. 창별 기록·작업 환경 저장본·동일성·저장소 버전과 원본 보존 경로를 만든다. 기존 모듈에 통합하고 병렬로 방치된 저장 구조를 만들지 않는다.
2. CaptureEngine/ProfileSlots의 수집·저장·제외·환경 전환을 새 단위로 연결한다.
3. RestoreEngine/RestoreSession/WindowGateway의 창별 대응·요청 수명·다시 열기·잠금 및 조작 보호를 연결한다.
4. PlugbackController와 설정 이전·지원 조건·정상 종료 저장을 연결한다.
5. 카드·확인 상세 창·직접 지정·포트와 Space 이름·로컬 진단을 연결한다.
6. 관련 검사를 통과시키고 구현 문서와 검증 상태를 갱신한다.

고정된 파일 분할을 강요하는 순서는 아니다. 깊은 모듈과 기존 PlugbackKit/App 경계를 유지하며 코드상 의존성에 맞춰 묶어 구현한다. 합의된 동작을 바꾸지 않는 구현 선택은 자율적으로 진행한다. 플랫폼 제약이 합의된 동작을 막는 경우에는 확인한 증거·영향·선택지를 보고한다.

## 현재 근거와 검증

- 새 설계 전체는 미구현이다. 현재 통과하는 옛 테스트가 새 계약을 검증한다고 간주하지 않는다.
- `Scripts/check-product-restore.sh`와 `Tests/DesignReviewTests/`는 현재 문제를 드러내는 별도 재현 검사다. 수정 전 일부 실패가 의도된 상태다. 새 모델에 맞춰 검사 입력·인터페이스를 갱신하되 R1–R6 문제의 검증 의도를 보존한다.
- 정책·저장·설정 이전·취소·늦은 관찰·부분 성공·창 중복 방지는 격리된 페이크와 임시 저장소로 검사한다. 필요한 `swift test`와 App의 표현 검사·macOS 빌드를 수행한다. 명령은 [빌드 절차](./BUILD_RUNBOOK.md)와 현재 프로젝트 설정을 확인해 사용한다.
- 실제 창 생성·다른 Space의 관찰·잠금 신호·독의 순차 연결·사용자 조작 충돌은 실기기 검증을 구별한다. 수행하지 않은 항목을 통과로 보고하지 않는다. 사용자의 실제 프로필을 테스트 데이터로 덮지 않는다.
- 현재 M2 Max 맥 한 대의 읽기 전용 IORegistry에서 USB-C 1=`left-back`, 2=`left-front`, 3=`right`와 LG HDR 4K의 3번·오른쪽 연결을 확인했다. 상세 필드와 한계는 상태 검토 1절에 있다. 동일 모델 여러 대·다른 맥·독 전체가 검증된 것은 아니다.
- 라이브러리·도구의 새로운 API 세부사항은 사용자 Context7 정책을 따른다. 이미 확인한 로컬 SDK·공식 문서 근거를 재사용할 수 있다. 브라우저 자동화는 Aside를 사용한다.

완료 시 변경한 동작·파일, 실제 실행한 검사와 결과, 남은 실기기 검증·제약을 구분해서 보고한다. 제품 구현 완료와 실기기 지원 검증 완료를 혼동하지 않는다. 이 요청은 로컬 구현 인계이며 배포·릴리스 요청은 아니다.

### 남은 실기기 검증과 제약

- **창 생성 경로:** 종료된 앱 실행(`NSWorkspace.openApplication`)·기본 창 되살리기·메뉴 「새 창」 항목 누르기(`openAdditionalWindow`)는 페이크로만 검증했다. 앱마다 항목 이름·지원이 다르며 실제 앱에서의 창 등장 시간·대응은 미검증이다.
- **사용자 조작 보호:** AX 이동 알림에는 누가 옮겼는지 정보가 없다. Plugback 자신의 이동 뒤 1초 안의 알림을 자기 이동으로 보는 추정이며, 다른 앱·입력 장치·OS 재배치와 겹칠 때의 오탐·누락은 실기기에서 확인해야 한다 (1.1절 검증표).
- **잠금 판정:** 세션 사전에 키가 없는 상태를 안 잠김으로 읽는다. 실제 잠금 중의 키 값, 잠금 해제 알림 순서, 잠긴 채 연결·복원 중 재잠금은 실기기 검증 항목이다.
- **개별 Spaces 설정:** `com.apple.spaces` `spans-displays`가 실제 설정 전환·재로그인 뒤 어떻게 바뀌는지 미검증. 관찰 교차 확인이 보완한다.
- **포트 위치:** M2 Max 한 대·LG HDR 4K 한 대의 USB-C 직결에서만 구조를 확인했다. 독·DisplayLink·다른 맥·동일 모델 여러 대는 미검증이며 못 찾으면 A/B로만 구분한다.
- **순차 연결 대기 시간:** 안정화 대기는 기존 1.5초를 유지했다. 짧은 재확인 값과 준비 판정은 연결·충돌 실험으로 조정한다. A 복원 중 B 추가 시 A 요청을 취소하고 A+B로 전환하는 흐름은 페이크로 검증했다.
