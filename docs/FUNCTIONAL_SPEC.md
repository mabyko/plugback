## F-01. 화면 감지 및 복원 트리거

> 조건들이 어느 순서로 어느 층에서 걸리는지는 [RESTORE_FLOW.md](./RESTORE_FLOW.md)에 그림으로 있다.

### F-01.1 작업 환경 전환이 복원 트리거다
연결된 외장 화면 식별자의 집합이 **작업 환경**이다(D5). 안정된 조합이 이전과 달라지면 다음을 순서대로 한다.

1. 자동 저장이 켜져 있으면 떠나는 작업 환경의 저장 대기 이력을 확정한다(F-03.5). 화면 추가로 떠날 때도, 분리로 떠날 때도 같다.
2. 새 조합의 작업 환경을 선택한다. 진행 중이던 이전 환경의 복원 요청은 「작업 환경 변경」으로 취소한다.
3. 복원 모드가 자동이고 새 환경의 저장본이 있으며 권한이 있으면 그 저장본으로 새 복원 요청을 시작한다. 저장본이 없으면 현재 배치를 유지하고 카드에 저장본 없음을 표시한다.

A+B에서 B를 분리하면 A+B를 저장하고 A 환경을 선택한다. A만 연결된 채 안정되면 예전에 A+B를 썼다는 이유로 B를 기다리지 않는다. 외장이 모두 없어지면 떠나는 환경을 저장하고 복원하지 않는다. Plugback 실행 자체는 트리거가 아니다 — 이미 연결된 화면은 다음 변경을 판단할 기준선일 뿐이다(D8).

### F-01.2 이벤트 안정화 (Trailing 대기)
* 케이블을 꽂으면 화면 변경 이벤트가 3~6회 연속으로 발생한다.
* **마지막 이벤트 후 일정 시간(초기값 1.5초) 동안 추가 이벤트가 없을 때만** 조합을 판정한다. 짧은 재확인 뒤 준비된 조합부터 복원한다는 합의는 이 대기 값을 실측으로 조정할 여지를 남긴다.
* 원시 변경 신호가 오면 안정화 전부터 수집을 멈추고 이전 환경의 마지막 유효 이력을 보존한다. 안정화 뒤 흩어진 창을 이전 환경에 기록하지 않는다.
* 해상도가 0이거나 유효하지 않은 화면은 화면 목록에서 빠진다.

### F-01.3 화면 위상 게이트와 잠금
* 직전 외장 화면 식별자 집합과 비교해 실제로 바뀐 경우에만 F-01.1을 적용한다. 잠자기 해제, 덮개 여닫기, 밝기·해상도 변경은 집합이 그대로이므로 조용히 지나간다.
* 시스템 잠자기 해제 직후 일정 시간(초기값 2.5초)은 새 등장의 자동 복원을 억제한다.
* **잠금 미루기**: 잠긴 상태에서 새 화면이 추가되면 어느 화면인지 기억한 채 들고 있다가 잠금 해제 직후 한 번 처리한다. 미뤄둔 화면이 그사이 빠지면 미룰 것도 사라진다. 변경 신호가 잠긴 상태에서 도착했으면 안정화 전에 잠금이 풀려도 잠자기 억제에 삼켜지지 않는다.
* 잠금 여부는 잠김·안 잠김·판정 불가 셋으로 구별한다. 판정 불가는 잠금 해제로 취급하지 않고, 복원 요청의 미전송 조작을 보류하며 사유를 표시한다(F-02.6).
* 잠금 판정과 잠금 해제 알림은 SDK 헤더에 없는 이름을 쓴다 → [UNDOCUMENTED_APIS.md](./UNDOCUMENTED_APIS.md)

### F-01.4 화면 식별
* 외장 화면은 케이블을 다시 꽂거나 해상도를 바꿔도, 포트를 바꿔 꽂아도 **같은 식별자**로 인식되어야 한다. 동일 모델 두 대는 서로 다른 식별자를 가져야 한다.
* 식별에 실패하면 복원하지 않는다. 지문이 다르면 그 화면은 통째로 건너뛴다.

### F-01.5 개별 Spaces 지원 조건 (D6)
* 첫 구현은 macOS 「각각의 Spaces가 있는 디스플레이」가 켜진 구성을 지원한다. 화면마다 일반 Space가 하나뿐이어도 지원 대상이다.
* 설정이 꺼져 있거나 확인할 수 없으면 새 Space 기록의 저장과 복원을 보류하고, 기존 저장본을 보존하며 카드와 저장 결과에 지원 조건을 안내한다. Space 제약을 지운 위치 복원으로 조용히 전환하지 않는다.
* 판정은 설정 값과 관찰(연결된 화면 수와 Space 관찰의 화면 수)을 교차 확인한다.

## F-02. 선택 복원 엔진

### F-02.1 복원 요청과 소스 고정
1. 요청은 시작할 때 현재 작업 환경의 **복원 소스**(마지막 저장 완료본)를 고정한다. 수집 중인 이력·다른 환경의 저장본과 섞지 않는다.
2. 요청의 단위는 저장본의 **창 위치 기록**이다. 같은 앱의 창이 여럿이면 각각 결과를 갖는다(D1). 앱 전역 선점(화면 순서상 첫 화면만 담당)은 없다.
3. 제외한 앱의 기록은 결과에 넣지 않는다. 같은 환경에서 닫힌 것으로 확인한 기록은 「이 환경에서 닫아 건너뜀」이다(D9).

### F-02.2 Space 조건
| 저장 Space의 현재 상태 | 처리 |
|---|---|
| 목적 화면의 현재 Space | 창 대응으로 진행 |
| 목적 화면의 비활성 Space | 방문 대기 — 유효한 요청 동안 방문 이벤트를 기다린다 |
| 다른 화면에 잔류 | 이동 안내 — 사용자가 Mission Control에서 옮긴 뒤 방문 대기로 이어진다 |
| 현재 없음 | 확인 필요 — 번호가 같은 다른 Space를 대신 고르지 않는다 |
| snapshot 없음·판정 불가·전체화면 | 확인 필요 — 평면 복원으로 강등하지 않는다 |
| Space 정보가 없는 기록(구버전 이전) | 위치만으로 복원한다 |

### F-02.3 창 대응 (D3)
1. 후보는 같은 앱의 표준 창 중 이동할 수 있는 창이다. 전체화면(불명 포함)·다른 Space의 창은 후보가 아니고, 최소화 창은 「최소화된 창도 복원」이 켜졌을 때만 후보다. 어느 화면의 현재 Space에 있는 창이든 목적 화면으로 데려온다(연결 해제로 내장에 내려온 창 포함).
2. **확인된 창 연결**(저장·수집 때 관찰했거나 사용자가 직접 지정해 확정한 창)을 먼저 고정한다. 다른 자리에 연결된 창은 후보에서 뺀다.
3. 남은 후보는 전체 이동 거리가 가장 짧은 일대일 배정으로 고른다. 동률이면 크기 차이가 작은 쪽, 그래도 같으면 일정한 순서다. 후보가 자리보다 많으면 필요한 수만 고르고 나머지 창은 유지한다. 추정 배정이며 과거 창의 정확한 식별로 취급하지 않는다.
4. 「복원할 창 직접 지정」이 켜져 있고 후보가 둘 이상이거나 남은 자리가 둘 이상이면 자동 배정하지 않고 확인 필요로 남긴다. 사용자가 「복원 확인」 창에서 고르고 「남은 창 복원」을 누르면 적용하며, 성공한 연결은 다음 복원에 재사용한다. OFF 전환은 미확정 선택만 취소하고, ON 전환만으로 선택 창을 띄우거나 복원을 시작하지 않는다.
5. 같은 실제 창을 두 자리에 배정하지 않는다.

### F-02.4 창이 부족할 때 — 닫힌 환경과 다시 열기 (D9)
| 상황 | 실험실 OFF (최초값) | 「종료된 앱 다시 열기」 ON |
|---|---|---|
| 앱이 꺼져 있음 | 「꺼져 있어 건너뜀」 | 다른 환경·연결 해제 중 닫힌 것으로 확인한 자리가 있으면 앱을 실행(포커스 없음)하고 창을 기다린 뒤 다시 판정 |
| 실행 중·창 0개 | 「창이 없어 건너뜀」 | 「실행 중인 앱 창 되살리기」 ON일 때만 기본 창 하나를 열게 한 뒤 다시 판정 |
| 창이 하나 이상인데 자리보다 적음 | 있는 창만 배치, 나머지는 「창이 없어 건너뜀」 | 「부족한 창 추가로 열기」 ON일 때만 부족한 수만큼 창을 열게 한 뒤 다시 판정 |
| 닫힌 시점·환경을 알 수 없는 자리 | 위와 같음 | 앱 실행·창 생성을 보류하고 「확인 필요」에 사유 표시. 사용자가 직접 연 창은 「남은 창 복원」에서 대응 |
| 같은 환경에서 닫힌 자리 | 「이 환경에서 닫아 건너뜀」 | 같음 — 다음 저장 성공까지 채우지 않는다 |

* 되살리기 OFF는 추가 열기 ON으로 우회하지 않는다. 실행·생성 직전에 최신 설정을 다시 보고, 요청당 앱마다 같은 종류의 요청을 한 번만 보낸다. 이미 요청한 앱·창은 강제로 닫지 않는다.
* 실행·생성 뒤에도 창을 확인하지 못하면 「확인 필요 · 앱 실행·창 열기를 요청했으나 창을 확인하지 못함」으로 남긴다. 탭·문서 내용은 복구하지 않는다.

### F-02.5 이동 및 검증
* 창을 목표 위치·크기로 옮기고 **실제 창 위치를 다시 읽어 확인한다.** 허용치(초기값 5pt)를 넘으면 1회 재시도하고, 그래도 실패하면 실패로 기록하고 다음 창으로 넘어간다.
* 이미 목표 위치에 있는 창은 「이미 제자리」로 건너뛴다.
* 자동 복원 요청에서 요청 시작 뒤 사용자가 직접 옮긴 창은 「직접 옮기는 중이라 건너뜀」으로 보호한다. Plugback 자신의 이동은 사용자 조작으로 보지 않는다. 명시적 요청에는 적용하지 않는다.

### F-02.6 공통 실행 조건
* 실제 이동·재시도·앱 실행·창 생성 직전에 요청 유효성과 잠금 상태를 확인한다. 잠겨 있거나 판정할 수 없으면 아직 보내지 않은 조작을 멈추고 「잠금 해제 대기」「잠금 상태를 확인하지 못해 대기」로 남긴다. 잠금 해제가 확인되면 같은 환경의 유효한 남은 항목만 고정한 소스로 재개한다.
* 새 요청·새 저장 성공·작업 환경 변경·대상 제외·저장 기록 삭제·Plugback 종료는 남은 작업을 취소한다. 자동 복원을 끄면 자동으로 시작한 요청의 남은 작업만 취소하고 명시적 요청은 유지한다. 완료한 창은 되돌리지 않는다.
* 방문 대기·이동 안내는 유효한 동안 시간 제한 없이 이벤트를 기다린다. 대기용 반복 타이머나 주기 조회는 없다. 확인 필요는 「남은 창 복원」으로만 재개한다.
* 단축어는 실행 전 기기 잠금 해제를 요구한다. 별도 예약 기능은 없다.

### F-02.7 응답 없는 앱 방어
* 대상 앱이 응답하지 않아도 메뉴바 UI는 멈추지 않는다. 복원은 UI를 막지 않는 별도 실행 흐름에서 수행한다.
* AX 호출당 응답 대기 한도는 초기값 250ms다. 창 목록 조회가 한도를 넘기면 한 번은 넉넉한 한도(초기값 1초)로 다시 묻는다. 재시도까지 실패한 앱은 조회 실패로 구별하며 창 0개로 취급하지 않는다.

### F-02.8 비침해 보장
* 제외한 앱과 저장하지 않은 창은 어느 화면에 있든 위치와 크기를 변경하지 않는다. 내장 화면의 작업 공간은 재배치하지 않는다.
* 전체화면·Split View 상태를 해제하거나 재생성하지 않는다. Space를 만들거나 옮기지 않는다.

### F-02.9 결과
* 모든 저장 창이 결과에 남는다: 이동, 이미 제자리, 건너뜀과 사유, 방문 대기, 이동 안내, 확인 필요와 사유, 잠금 보류, 실패, 취소와 사유. 요약은 `이동 n · 건너뜀 n · 대기 n · 확인 필요 n · 실패 n · 취소 n`이며 0인 대기·확인·취소는 생략한다.
* 확인 필요·창 생성 실패·잠금 판정 실패는 진단 기록에 남긴다(F-05.8).

## F-03. 저장 엔진

### F-03.1 수동 저장
* 사용자가 `[💾 지금 레이아웃 저장]`을 누르면 연결된 작업 환경의 저장본을 한 번에 갱신한다. 관찰 도중 화면 구성이 바뀌면 저장하지 않고 이전 저장본과 이력을 유지한다.
* 저장 성공은 그 환경의 저장 대기 이력·닫힌 창 제외 목록·진행 중 복원 요청을 정리하고, 그보다 오래된 관찰이 늦게 도착해도 이력으로 받지 않는다.

### F-03.2 저장 대상
* 창의 **중심점이 위치한 화면**을 소속 화면으로 판정한다. 중심점이 작업 환경의 외장 화면에 있는 표준 창만 저장한다.
* 최소화·전체화면(불명 포함)·숨긴 앱(⌘H)의 창은 저장하지 않는다.
* Space를 관찰하는 실행에서는 **현재 Space에 있는 창만** 이번에 확인한 것으로 기록한다. 비활성 Space·잔류 Space·판정 불가 창은 기존 기록을 유지한다. Space를 차례로 방문해 저장하면 기록이 누적된다.
* 화면별 일반 Space 목록(식별 가능한 것)을 함께 저장한다.

### F-03.3 앱 포함과 창별 병합 (D4)
* 외장 화면에 나타난 표준 창의 앱은 처음이든 이후든 **기본 포함**한다. 사용자가 제외한 앱만 뺀다. 수동·자동 저장에 같은 규칙을 적용한다.
* 창 하나가 기록 하나다. 관찰한 창이 기존 자리에 연결돼 있으면 그 자리를 갱신하고(같은 창의 화면·Space 이동 포함), 연결이 없으면 같은 앱·화면·Space의 연결 없는 자리를 가까운 순서로 이어받으며, 그것도 없으면 새 자리를 만든다. Space가 없는 자리(구버전 이전·flat 저장)는 같은 앱·화면의 어느 Space 창이든 이어받아 Space를 지정한다 — 다시 저장하면 중복이 아니라 승격이다. 같은 앱·화면의 창을 Space와 함께 확인했는데 남아 있는 Space 없는 자리는 그 기록에 흡수된 것으로 보고 뺀다.
* 관찰하지 못한 기존 자리는 유지한다. 같은 환경에서 닫힌 것으로 확인한 자리와 연결을 유지한 채 내장 화면으로 옮긴 창의 자리는 다음 저장에서 뺀다. 내장 이동은 **같은 환경에서 외장 화면에 있는 것을 확인한 뒤** 내장에서 발견한 창에만 적용한다. 화면 분리·재연결로 macOS가 내장에 모은 창은 아직 외장에서 확인하지 않았으므로 기록을 보존한다(W17).
* 제외한 앱의 창은 관찰하지 않는다. 제외는 저장·복원 대상에서 빼는 것이지 기록을 지우는 것이 아니다 — 저장본과 저장 대기 이력의 기록이 그대로 남는다(US-006 AC-2).
* 허용 오차(F-02.5의 값) 안의 차이로는 좌표를 갱신하지 않는다(드리프트 방지).

### F-03.4 좌표 저장 형식
* 창 위치는 소속 화면 크기에 대한 **비율 좌표**로 저장한다. 픽셀 절대 좌표는 저장하지 않는다. 화면이 음수 좌표 영역에 있어도 올바르게 계산한다.

### F-03.5 자동 저장 (D2·D7)
* 일반 설정 「자동 저장」은 선택 이력이 없으면 ON이다. 사용자의 선택은 유지한다.
* ON이면 창 이동 정착·앱 전환·앱 종료·Space 전환·Mission Control 닫힘에 반응해 현재 상태를 **저장 대기 이력**으로 수집한다. 이력은 메모리에만 있고 복원 기준을 바꾸지 않는다.
* 저장 완료 시점은 **작업 환경을 떠날 때**(F-01.1)와 **Plugback 정상 종료 전**이다. 마지막 저장본과 내용(화면별 Space 목록, 창별 화면·Space·위치·크기)이 같으면 생략하고 저장 시각도 올리지 않는다. 닫힌 창 제외가 남아 있으면 정리를 위해 저장한다.
* 수동 저장보다 오래된 관찰, OFF 전에 시작한 관찰은 이력이 되지 않는다. OFF는 저장 전 이력을 지우고 마지막 저장본을 유지한다. 다시 ON이면 그 뒤의 관찰부터 새로 모은다.
* 복원 직후의 착지 위치는 사용자가 그 창을 옮기기 전까지 새 이력으로 승격하지 않는다. 복원의 중간·실패 배치가 다음 복원 기준이 되지 않는다.
* 방문 대기가 남아 있어도 확인된 다른 Space의 사용자 변경은 이력에 모은다. 복원이 실행되는 구간과 화면 구성 변경 신호 뒤 안정화 전에는 수집하지 않는다.
* 자동 저장 OFF에서도 창 연결과 닫힘 판정(F-03.6)은 계속한다.

### F-03.6 창 연결과 닫힌 창 (D9)
* 저장·수집 때 관찰한 창은 저장 자리와 실행 중 창 ID로 연결된다. 연결은 메모리에만 있으며 재실행을 넘지 않는다.
* 연결된 창이 사라진 것을 관찰하면 어느 작업 환경에서 관찰했는지 기록한다. 앱 종료 알림도 같은 관찰이다. 조회에 실패한 앱의 창 부재는 닫힘으로 판정하지 않는다.
* 창 부재의 근거는 **존재하는 창 전부의 WindowServer 목록**(`CGWindowListCopyWindowInfo`, 다른 Space·최소화·숨김 포함)이다. 표준 창 열거(AX)는 다른 Space의 창을 돌려주지 않으므로(실측 2026-09-11) 열거에서 빠진 것만으로는 닫힘이 아니다. 목록을 얻지 못하면 판정하지 않는다.
* **같은 환경에서 닫힌 자리**는 그 환경의 다음 저장 성공까지 복원에서 제외한다. 이 제외는 파일에 보존되어 시간 경과·재연결·Plugback 재실행으로 풀리지 않는다. 저장 실패·취소·다른 환경의 저장도 풀지 않는다.
* 다른 환경·연결 해제 중 닫힌 자리는 유지되고 F-02.4의 다시 열기 옵션에 따른다. 연결이 없는 자리(재실행 뒤 등)는 닫힌 시점·환경을 알 수 없는 자리다.

### F-03.7 정상 종료 전 저장
* 자동 저장 ON이고 저장할 변경이 있으면 종료를 허용하기 전에 저장을 완료한다. 실패하면 종료를 취소하고 「다시 시도」「저장하지 않고 종료」「취소」를 묻는다. 이력과 기존 저장본은 그대로다.
* 강제 종료·충돌 뒤에는 마지막 저장 완료본만 복원 소스다. 저장 전 이력의 유실은 예외로 허용한다.

## F-04. 저장소

### F-04.1 구성
작업 환경 기록 하나는 다음을 가진다.

* 작업 환경 키(외장 화면 식별자 집합)
* 화면 정보: 식별자, 표시 이름, 지문(검증용), 마지막 확인 포트 위치(표시용), 저장된 일반 Space 목록
* 앱 선택: 앱 식별자, 표시 이름, 포함 여부
* 창 위치 기록: 저장 자리 identity, 앱, 목적 화면, 저장된 Space(없을 수 있음), 비율 좌표
* 마지막 저장본의 시각과 방식(수동/자동), 같은 환경에서 닫힌 자리의 제외 목록

### F-04.2 저장소
* 사용자 라이브러리 영역의 `workspaces.json`에 보관한다. 버전 필드를 두어 이후 형식과 손상을 구별한다.
* 파일이 손상되어 읽을 수 없으면 백업 후 초기화하고 알린다. 백업에 실패하면 원본을 덮지 않고 읽기 실패로 취급한다.
* 파일이 존재하는데 읽지 못하거나 이후 버전이면 **첫 실행으로 위장하지 않는다** — 그 실행의 모든 저장·변경을 거부한다. 상세 알림을 닫아도 금지는 유지된다.
* 쓰기가 실패하면 새 상태를 메모리에 먼저 공개하지 않고 이력·제외 목록을 보존한다. 다음 저장에서 다시 시도한다.

### F-04.3 구버전 이전
* 구버전 `profiles.json`(화면별 프로필)은 `workspaces.json`이 없을 때 한 번 읽어 **화면 하나짜리 작업 환경**으로 가져온다. 앱당 좌표 하나가 Space 없는 창 위치 기록 하나가 된다. 화면 조합·개별 창·Space 정보는 지어내지 않는다.
* 구버전 실험실 「자동 슬롯」이 켜져 있었으면 더 최근 자동 슬롯을 복원 소스로 이어받는다. 앱의 포함·제외 선택은 보존한다.
* 원본 파일은 수정·삭제하지 않는다. 설정 창이 이전 사실과 「여러 화면 조합·Space별 위치는 다시 저장해야 기록됨」을 안내한다.
* 설정도 한 번 이전한다: 「자동 슬롯」 선택 → 「자동 저장」, 「창이 없는 앱은 새 창을 열어 복원」 → 「실행 중인 앱 창 되살리기」. 새로 생긴 「종료된 앱 다시 열기」「부족한 창 추가로 열기」「복원할 창 직접 지정」은 자동으로 켜지 않는다. 새 키에 이미 값이 있으면 덮지 않는다.

## F-05. 메뉴바 UI

### F-05.1 상태 표시
* 헤더: 연결된 외장 화면 이름과 저장본 유무. 여러 대면 「첫 화면 외 N대」.
* 화면 표시 이름은 모니터 이름 + 포트 위치, 구분이 안 되면 A/B다. 화면별로 묶어 보여주고, 단독 항목(대기 줄·안내·확인 목록)에도 화면 이름을 붙인다. Space 번호는 화면별 일반 Space의 현재 순서로 1부터 붙이며 전체화면 항목은 제외한다. 현재 순서를 확인할 수 없으면 저장 순서의 번호와 확인 불가 상태를 구분한다.
* 복원 소스 줄: 「복원 소스 · 수동/자동 · 시각」. 자동 저장 ON이면 저장 대기 이력 줄(「저장 대기 · n분 전 배치 — 환경을 떠날 때 저장」 / 「대기 중 변경 없음 · 확인 n초 전」)을 함께 보여준다.
* 진행 중 요청: 「화면 연결 확인 중」, 방문 대기·이동 안내·잠금 보류 줄(화면 이름 · Space N …), 「창 확인 필요 N개」 버튼, 「남은 창 복원」「남은 복원 취소」 버튼.
* 마지막 복원 결과: F-02.9의 요약과 펼칠 수 있는 저장 창별 사유. 결과에는 시각을 붙인다.
* 저장 직후 일회성 확인 「저장됨 · 앱 n개 · 창 n개」, Space 관찰 실패·개별 Spaces 미지원 안내, 지문 불일치 경고, 저장소 문제는 각각 별도로 보여준다.

### F-05.2 동작 버튼
* `[💾 지금 레이아웃 저장]`, `[↶ 지금 복원]`. 저장본이 없으면 저장을, 있으면 복원을 강조한다. 복원 진행 중에는 진행 표시로 바뀌고 저장·재복원은 거부된다.
* 저장 차단 실행에서는 저장 버튼을 비활성화한다.

### F-05.3 대상 앱 목록
* 목록은 화면마다 세 묶음이다. 기준은 「지금 이 화면에 창이 있나」다 — 첫인상이 지금 화면과 맞아야 무엇이 저장될지 보인다.
  * **지금 화면에 있는 앱**(첫 묶음, 항상 펼침): 저장했든 아직이든 외장 화면에 표준 창이 있는 포함 앱. 체크가 켜져 있고, 아직 기록이 없는 앱에는 「저장 전」을 붙인다. 다음 저장의 대상이다(D4).
  * **화면에 없는 저장 앱 N개**(접힘): 기록은 있지만 지금 이 화면에 창이 없는 포함 앱. 복원 대상은 유지된다. 실행 중이 아니면 「꺼짐」을 붙인다.
  * **제외한 앱 N개**(접힘): 사용자가 체크를 끈 앱. 창이나 기록이 있는 화면에 보이고, 어디에도 없으면 첫 화면 묶음에 모은다. 체크를 끈 직후에는 그 화면의 이 묶음을 펼쳐 둔다.
* 체크박스는 한 질문에만 답한다 — **「이 앱을 다루나」**. 작업 환경 전체에 적용된다. 끄면 저장·수집·복원에서 빠지되 창 위치 기록은 남는다. 저장 기록 삭제는 별도 동작이며, 삭제한 앱의 창이 외장 화면에 남아 있으면 첫 묶음에 「저장 전」으로 돌아온다.
* 같은 앱의 창이 여럿이면 창 수를 붙인다. 보드 레이아웃은 첫 묶음을 격자로, 나머지 둘을 「그 외」로 보여준다.

### F-05.4 복원 모드
* 자동(기본값): 작업 환경 전환 시 즉시 복원. 수동: 버튼·단축어로만. 수동으로 바꾸면 자동으로 시작한 요청의 남은 작업만 취소하고, 다시 자동으로 켜도 즉시 복원하지 않는다.

### F-05.5 단축어
* 복원을 시스템 단축어의 동작으로 제공한다. 기본 전역 단축키는 없다. 실행 전 기기 잠금 해제를 요구한다. 응답은 복원의 반환값 그대로다 — 결과 요약 · 권한 없음 · 외장 화면 없음 · 이미 복원 중 · 저장본 없음 · 개별 Spaces 미지원.

### F-05.6 설정 창
* 모양 · 일반 · 작업 환경 · 실험실. 일반에는 로그인 시 실행, **자동 저장**, 「최소화된 창도 복원」, 단축키 안내. 작업 환경에는 저장된 모든 작업 환경(연결 여부 무관)의 화면 이름·앱 수·창 수·복원 소스와 삭제(확인 한 번). 실험실에는 「종료된 앱 다시 열기」와 자식 「실행 중인 앱 창 되살리기」「부족한 창 추가로 열기」, 「복원할 창 직접 지정」, 진단 기록 내보내기. 실험실 설정은 모두 최초 OFF이며 부모 OFF일 때 자식 값은 유지되지만 동작하지 않음을 안내한다.

### F-05.7 「복원 확인」 창
* 카드의 「창 확인 필요 N개」를 눌렀을 때만 연다. 확인이 필요한 저장 창마다 앱 아이콘·이름, 화면 표시 이름, Space 번호, 저장 위치, 사유를 보여준다. 같은 앱의 여러 창도 개별 항목이다.
* 직접 지정이 켜져 있으면 모호한 항목에서 현재 후보 창을 고르고 「창 확인」으로 앞으로 가져올 수 있다. 창 제목은 표시용이며 저장·진단에 넣지 않는다. 저장 자리 삭제도 여기서 할 수 있다.
* 「남은 창 복원」이 유일한 재개 경로다. 창을 열고 닫는 것은 복원을 시작하지 않는다. 키보드로 조작할 수 있고 사유는 색상만으로 전달하지 않는다.

### F-05.8 진단 기록
* 확인 필요·창 생성 실패·잠금 보류 사례를 로컬 `diagnostics.json`에 최근 100건까지 남긴다. 같은 요청·저장 창·사유의 반복은 한 건이다. 앱 식별자, 요청 시작 방식, 저장 창 수·관찰 창 수·후보 수, 화면 수, Space 관찰 상태, macOS 버전만 담는다. 사용자가 설정에서 내보낼 때만 파일로 제공하며 자동 원격 전송은 없다. 기록 실패는 저장본·복원 결과를 바꾸지 않는다.

## F-06. 권한 및 시작 프로그램

### F-06.1 권한 단일화
* '손쉬운 사용(Accessibility)' 권한 하나로만 동작한다. 화면 기록 권한은 요구하지 않는다. 창 열거는 실행 중인 앱을 순회하는 경로만 사용한다.

### F-06.2 권한 온보딩
* 권한이 없으면 기능을 시도하지 않고 시스템 설정으로 안내한다. 권한 획득 후 재시작 없이 정상 동작한다. 권한 없이 얻은 빈 창 목록으로 저장본이나 창 연결을 바꾸지 않는다.

### F-06.3 로그인 시 자동 실행
* 켜고 끌 수 있다. 기본값은 켬.

## F-08. 실험실

모든 실험실 설정은 선택 이력이 없으면 OFF이고, 사용자가 바꾼 값은 재시작·설정 이전 뒤에도 유지한다. 걷어낼 수 있어야 실험이므로 설정 창의 별도 구획에만 둔다.

| 설정 | 동작 |
|---|---|
| 종료된 앱 다시 열기 (부모) | F-02.4. OFF면 앱 실행·명시적 창 생성 전체를 막고 기존 창 배치는 유지한다. ON 전환이 자식 값을 켜지 않는다 |
| 실행 중인 앱 창 되살리기 (자식) | 실제 창 0개일 때 기본 창 하나 열기 허용 |
| 부족한 창 추가로 열기 (자식) | 창 하나 이상일 때 부족분 추가 열기 허용. 되살리기 OFF를 우회하지 않는다 |
| 복원할 창 직접 지정 | F-02.3의 4. OFF 전환은 미확정 선택만 취소, ON 전환은 앞으로 배정할 모호한 창에만 적용 |

탭·문서 내용 복구는 이번 범위가 아니며 이를 위한 설정·저장 필드도 두지 않는다.

## 부록. 구현 주의사항

1. **전체화면 창은 이동이 조용히 실패한다.** 좌표 설정 호출이 성공을 반환하고 창은 그대로 있다. 검증(F-02.5) 없이는 감지할 수 없다.
2. **좌표계가 두 개다.** 접근성 API는 좌상단 원점, 화면 정보 API는 좌하단 원점을 쓴다. 하나로 통일하지 않으면 화면을 세로로 배치한 환경에서만 창이 사라진다.
3. **창에는 앱 재시작을 넘어 유효한 식별자가 없다.** 실행 중 창 ID(WindowServer)는 같은 실행 안에서만 같은 창을 뜻하며 파일에 저장하지 않는다. 재실행 뒤의 대응은 추정 배정이고, 빈 자리는 닫힌 환경을 알 수 없는 자리다.
4. **창 이동 알림은 드래그 중에도 온다.** Chrome 실측(2026-09-11)에서 버튼을 누른 동안 같은 창의 이동 알림이 반복됐다. 사용자 조작 판정은 Plugback 자신의 이동과 대조한 추정이며, 다른 앱·입력 장치에서의 정확도는 실기기 검증 항목이다.
5. **포트 위치는 표시용이다.** IORegistry의 DisplayPort 전송 노드와 USB-C 포트 노드를 EDID로 대응시켜 얻는다. 독·DisplayLink·다른 맥 모델에서는 못 찾을 수 있고, 그때는 A/B만 붙는다.
