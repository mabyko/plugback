# Plugback 재설계 제안

상태: 통합 검토 제안과 구현 기록 · 2026-10-20. 제안 자체를 모두 확정한 것은 아니며, 사용자가 구현을 요청한 뒤 반영한 범위는 아래 구현 기록에 구분한다. 현재 동작의 기준은 `FUNCTIONAL_SPEC.md`다.
Codex의 구현·화면 검토와 [Claude-dev-max / Opus 5.5의 독립 검토](./2026-10-20-claude-redesign-review.md)를 비교·통합했다. 아래 재현 결과와 제안은 구분한다.

## 제품의 중심 질문

**다른 작업 환경을 거쳐 돌아왔을 때, 내가 저장한 창은 제자리로 돌아왔나? 남은 일이 있다면 무엇인가?**

일반적인 창 정리 도구로 확장하기보다 이 질문에 답하는 경험을 완성한다. 평소에는 자동으로 동작하고, 메뉴바를 열면 복원 기준·결과·다음 행동을 이해할 수 있어야 한다.

## 사용자 우선순위와 검토 범위

사용자 추가 방향: **세 축을 모두 점검하되 1번 복원 흐름·신뢰성을 기본으로, 2번 디자인·사용감을 함께 챙긴다.**

| 축 | 이번에 답할 질문 | 제안 |
|---|---|---|
| 3 · 제품 범위 | 이 제품이 꼭 해결해야 할 문제는 무엇인가? | 다른 작업 환경을 거쳐 돌아왔을 때 대상 창의 배치를 되찾는 일. 타일링·전체 세션 복구로 확장하지 않는다. |
| 1 · 복원 흐름·신뢰성 | 저장 기준과 결과가 일치하며, 중단·변경·실패를 예측할 수 있는가? | 기존 보호 규칙을 보존하고 결과 소유권·경쟁·재개 경로를 먼저 검증한다. 모든 디자인의 수용 조건이다. |
| 2 · 디자인·사용감 | 무엇이 됐고 무엇을 해야 하는지 쉽게 읽히며 사용하기 편한가? | 차분한 네이티브 카드, 상태별 문장과 행동, 필요할 때 상세로 들어가는 정보 구조를 적용한다. |

검토 순서는 3→1→2이고 우선순위는 1이 가장 높다. 미적 완성도는 글자 위계·정렬·간격·상태 전환·빛/어둠·키보드 사용까지 포함한다. 화면에서 불편한 대기·오류를 감추어 간결함을 만들지 않는다.

범위 점검 결과: 기본 포함/사용자 제외, 작업 환경별 저장, 자동 저장, 안내형 Space 복원, 실험실의 재열기/직접 지정은 유지한다. 설명이 복잡한 고급 옵션은 실험실에 남기고 기본 카드의 첫 화면에는 넣지 않는다. 자동 저장 기본값이나 복원 방식 변경은 이번 시안의 전제가 아니다.

| 우선 | 문제 | 근거 수준 | 수정의 완료 조건 |
|---|---|---|---|
| 1 | 화면 집합이 바뀌지 않는 원시 화면 변경 뒤 `isSettlingScreens`가 해제되지 않음 | 임시 테스트 재현 T1 | 안정화 완료는 변화 유무와 상관없이 통지하며, 해상도 변경 뒤 상태 문구가 해제됨 |

| 3 | 저장 기록·자리 삭제가 확인 없이 실행되는 경로가 있음 | 코드 확인 | 삭제와 제외를 구별하고 되돌릴 수 없는 삭제는 한 번 확인함 |

T1~T6의 코드·경로·검증 한계는 독립 검토 부록 A에 있다. 재현 단언은 **현재 문제 동작**을 기대하므로 통과가 수정 완료를 뜻하지 않는다. 구현 단계에서는 기대하는 올바른 동작을 단언하는 회귀 검사로 바꾼다.

### 함께 채택하는 방향과 조정한 부분

- 제품 범위와 저장·복원 정책 모듈은 유지한다. 화면과 결과의 기준은 작업 환경으로 통일한다.
- 현재 기본 시안과 Claude의 시스템 패널안은 상태 위계·네이티브 컨트롤·상세로 들어가는 흐름에서 일치한다. 첫 구현은 시스템 컨트롤·서체·재질을 우선하며, 시안의 Sage 색은 시각 방향의 예시다. 색상 선택 기능 제거는 이번 결론에 포함하지 않는다.
- 실행 종료 후 모인 일을 처리하는 공통 경로와 안정화 완료 통지를 채택한다. 처음부터 공개 `send(CoreEvent)`·`CoreState`로 전면 이전할 필요는 없다. 기존 명령 Interface를 유지하고 내부 실행 배선부터 일치시킨다. 이 방법으로 문제가 해결되는지 본 뒤 공개 Interface 변경 필요성을 판단한다.
- 안전에 필요한 취소·제외·원시 화면 변경·권한 회수·잠금 정보는 즉시 유효성/실행 게이트에 반영해야 한다. 이런 신호까지 실행 뒤로 미루는 직렬 큐는 채택하지 않는다. 지연·합치기는 환경 재선택·남은 항목 재판정·수집 같은 후속 작업에 한정한다. `@MainActor`만으로 await 구간의 재진입이 방지되는 것도 아니다.
- 기존 자동 저장 ON과 마지막 저장 완료본 정책을 유지한다. 자동 저장 OFF나 별도 수동 우선 슬롯으로 되돌리는 선택은 필요하지 않다. 낡은 약속 문구를 현재 합의에 맞추는 것이 기본안이다.
- 독립 검토 I2의 「내장 화면의 창을 옮기지 않음」은 저장된 대상 창이 내장에 모인 경우 외장으로 데려오는 것까지 금지한다는 뜻으로 적용하지 않는다. 아래 보존할 약속과 최소 요구사항 2장 다를 따른다.
- 메뉴바의 정적 상태 표시는 후속 선택지다. 먼저 카드 자체의 정확성과 필수 흐름을 완성한다.

## 보존할 약속

- A와 A+B는 서로 다른 작업 환경이다. 내장 화면은 키에 포함하지 않는다.
- 저장 대상은 외장 화면 일반 Space의 표준 창 하나다. 제외한 앱의 기록은 남는다.
- 내장 화면의 배치를 저장하거나 Space를 옮기지 않는다. 저장된 대상 창이 케이블 분리로 내장에 모인 경우에는 외장 화면으로 데려올 수 있다. 내장 화면의 모든 창을 무조건 이동 금지한다고 표현하지 않는다.
- 수집과 저장 완료는 다르다. 자동 저장은 기본 ON이며 환경 이탈·정상 종료 시 유효 이력을 확정한다. 복원은 마지막 저장 완료본을 사용한다.
- 복원 요청은 소스를 고정한다. 재실행을 넘는 창 동일성을 약속하지 않는다.
- 방문 대기·이동 안내·확인 필요·잠금 보류·실패는 각각 다른 의미다. 확인 필요는 명시적 재개로만 다시 판정한다.
- 기본 구성에서는 앱을 실행하거나 창을 만들지 않는다. 실험실 옵션은 최초 OFF다.
- 손쉬운 사용 권한 하나, 이벤트 기반 대기, 로컬 진단을 유지한다.

기준: `CONTEXT.md`, `FUNCTIONAL_SPEC.md` F-01~F-08. 최소 요구사항과 문구가 충돌하는 자동 저장 설명은 여기서 새로 합의한 것으로 처리하지 않는다.

## 디자인 방향

| 방향 | 좋은 점 | 비용 | 추천 |
|---|---|---|---|
| 상태 중심 카드 | 연결 환경·현재 결과·다음 행동을 한 번에 읽는다. 평소 열 필요가 적다. | 앱 관리는 한 단계 더 들어간다. | 기본안 |
| 작업 환경 탐색기 | 여러 화면·Space·앱을 비교하기 쉽다. | 메뉴바가 상시 관리 도구처럼 커진다. | 앱 관리/복원 확인 화면에서 사용 |

이 제품만의 시각적 요소는 **화면별 저장 자리와 현재 복원 결과**다. 장식용 통계 대신 작은 화면 윤곽과 이름으로 범위를 표시한다. 추천 카드 폭은 380pt 전후(실제 구현에서 글자 크기·번역·VoiceOver 확인 후 조정), 16~20pt 안쪽 여백, SF 계열 시스템 글꼴, 단일 Sage 계열 강조색이다. 위험·대기·성공은 아이콘과 문장을 함께 사용한다. 모양은 시스템 밝기/어둡기를 따른다.

큰 상태 제목은 18~20pt, 본문 13~14pt, 보조 설명 12~13pt를 출발점으로 삼는다. macOS 컨트롤의 키보드 포커스와 접근성 설정을 우선한다. 웹 시안은 모바일에서도 문서 검토가 되도록 줄바꿈하며, 모바일 앱을 제안하는 것은 아니다. 동작 피드백은 약 120~180ms, 동작 줄이기 설정에서는 전환 효과를 줄인다.

### 레퍼런스 적용

- [Taste Skill](https://github.com/Leonxlnx/taste-skill)과 [app screens 문서](https://github.com/Leonxlnx/taste-skill/blob/main/skills/taste-skill/references/app-screens.md): 제품의 실제 대상에서 시각적 중심을 만들고, 차분한 표면·정직한 상태·정렬된 목록을 사용하며 실제 화면을 보고 수정한다는 원칙을 참고했다. 도구 설치·외부 스크립트 실행은 이 제안의 전제 조건이 아니다.
- [Lucian UX/UI Prompt](https://lucianlabs.dev/uxui-prompt/): 083 대기→진행, 288 상세 펼치기, 355 저장 상태 표현을 상호작용 참고 항목으로 선택했다. 원문 패턴을 제품에 적용한 부분은 이 제안자의 해석이다. 실제 저장 완료 시점은 Plugback 규칙을 따른다.
- `ui-ux-pro-max`의 정보 위계·키보드 접근·상태별 복구 경로 원칙을 적용했다. 검색 결과의 랜딩페이지 구조와 웹폰트 추천은 macOS 메뉴바에 맞지 않아 채택하지 않았다.

## 화면과 사용자 흐름

### 메뉴바 카드

1. 작은 제품명과 작업 환경: 실제 화면 표시 이름, 외장 화면 수, 연결 여부.
2. 가장 중요한 상태: `복원할 준비가 됐어요`, `창 2개가 Space 방문을 기다려요`, `창 1개를 확인해 주세요` 등. 준비됨은 복원 완료를 뜻하지 않는다.
3. 그 상태에서 가능한 행동: 첫 저장이면 저장, 준비 상태면 지금 복원, 확인 필요면 확인 열기. 대기 중에는 취소와 남은 창 복원도 제공한다.
4. 복원 기준: 마지막 **저장 완료** 방식·시각. `저장 대기`와 구분한다.
5. 앱 관리: 현재 포함 앱 수와 창 기록 수. 누르면 기존 세 묶음과 Space 필터를 제공한다. 필터는 복원 범위를 바꾸지 않는다.
6. 마지막 요청 결과: 요청 시각, 복원된 창·이미 제자리·건너뜀·대기·실패·취소의 세부 사유. 예전 결과는 현재 상태와 별도 표기한다.
7. 자동 복원 전환과 설정. 자동 저장 설정은 설정 창에서 별도로 설명한다.

저장 실패가 있어도 이전 읽기 가능한 저장본은 남는다. 상태 문구와 저장 동작의 오류를 별도로 보존해, 실패 안내 때문에 현재 복원 결과를 덮지 않는다. 한 창에 여러 사유가 겹치면 도메인의 기존 판정을 사용하고 표시 계층에서 새 규칙을 만들지 않는다.

### 처음 사용하는 흐름

`권한 설명 → 시스템 설정 열기 → 권한 재확인 → 외장 화면 확인 → 현재 창/Space 범위 설명 → 첫 저장 → 저장 완료`

권한이 없을 때 빈 창 관찰을 저장하지 않는다. 화면이 없으면 연결을 안내한다. 첫 저장은 현재 확인한 Space만 새로 기록하고, 다른 Space의 저장을 약속하지 않는다. 권한 획득이나 Plugback 실행 자체로 복원을 시작하지 않는다.

### 평상시와 남은 작업

- 돌아온 작업 환경: 안정화 → 소스 고정 → 가능한 창 복원 → 결과 표시. 자동 팝업을 띄우지 않는다.
- 방문 대기: `Studio Display · Space 2를 열면 이어서 복원해요`. Space를 앱이 열어주는 버튼으로 오해시키지 않는다. OS에서 방문하면 유효한 요청만 재판정한다.
- 이동 안내: 출발 화면·목적 화면·Space를 적고 Mission Control에서 사용자가 해야 할 일을 설명한다. Plugback이 Space를 직접 옮기지 않는다.
- 확인 필요: 이유와 현재 후보를 확인하고, 사용자가 남은 창 복원을 실행한다. 후보 선택만으로 자동 이동하지 않는다.
- 잠금 보류: 완료된 결과와 소스를 유지한다. 해제 후 환경과 요청이 유효한 남은 작업만 재개한다.
- 저장 실패: 이전 저장 시각을 유지하고 원인·재시도를 제공한다. 종료 시 저장 실패의 세 선택지는 기존 규칙을 보존한다.

## 로직 재설계

### 상태는 소유권을 나누고, 표시는 한 번 계산한다

하나의 거대한 UI 상태 enum으로 모든 조합을 강제하지 않는다. 아래 사실을 각각 원래 소유자에게 둔다.

| 소유자 | 갖는 사실 | 수명 |
|---|---|---|
| `WorkspaceLibrary` | 저장 완료본·앱 선택·닫힌 자리 제외·저장 차단 | 작업 환경별 영속 상태 |
| `RestoreSession` | 요청 ID·작업 환경 키·고정 소스·시작 방식·창별 결과·명시적 선택 | 유효한 요청 동안 메모리 |
| 기존 watcher/observation | 연결 안정화·현재 창·Space·잠금 판정 | 관찰 시점 |
| `PlugbackController` | 명령 조정·이벤트 배선·작업 환경 전환 | 앱 실행 동안 |
| 새 순수 표시 계산 | 제목·심각도·가능한 행동·사유별 줄 | 위 사실에서 매번 계산 |
| SwiftUI 화면 | 펼침·탐색·검색·포커스 | 화면 탐색 동안 |

새 표시 계산의 외부 Interface는 `present(facts) -> CardState` 하나로 시작한다. `CardState`에는 context, headline, notices, primaryAction, secondaryActions, source, appSummary, requestDetails를 둔다. 이름은 구현 시 조정한다. 권한·실행·저장 차단·요청 유효성은 사실로 입력하고 View에서 별도 재판정하지 않는다. 기존 `CardPresentation`에 이 계산을 모으는 방식으로 시작하며 추상 프로토콜이나 새 패키지는 필요 없다.

도메인 명령 Interface는 기존 `captureNow`, `restoreNow`, `resumeRemaining`, `cancelRemaining`, `setTracked`를 유지한다. View는 행동 ID를 기존 명령에 연결한다. 명령 실행 직전의 안전 검사는 기존 도메인이 계속 맡는다. App Intent는 카드의 표시 상태를 거치지 않고 기존 명령 반환값을 사용하며 결과 문구 계산만 공유할 수 있다.

### 결과 소유권

화면 ID만으로 결과를 공유하지 않고 최소한 `(workspaceKey, requestID)`에 묶는다. 요청에 고정 소스와 시작 시각을 함께 둔다. 새 저장 성공 시 이전 소스의 대기 항목을 취소하고, 남기는 결과에는 이전 요청 시각을 붙인다. 작업 환경 변경 시 현재 환경의 요청 결과만 투영한다. 앱 재실행으로 미완료 요청을 되살리지 않는다.

기존 `RestoreSession.Request`의 소스·ID를 먼저 재사용한다. 화면 결과 캐시는 필요성을 검증하고 줄인다. 과거 요청 이력 데이터베이스나 새 파일 포맷은 이 요구에 필요하지 않다.

### 이벤트 순서와 경쟁 처리

1. 원시 화면 변경 신호에서 새 수집을 중지한다.
2. 전환 전 확보한 유효 이력을 이전 작업 환경에 저장한다. 실패하면 이전 저장 완료본·이력을 보존하고 오류를 노출한다.
3. 화면 조합 안정화 후 작업 환경을 확정하고 이전 환경의 요청을 무효화한다.
4. 자동 복원 조건을 만족하면 새 환경의 마지막 저장 완료본을 고정해 요청을 시작한다.
5. `DesktopObservation`의 관찰로 `RestoreEngine.plan`을 계산하고 기존 `RestoreSession`이 실행한다.
6. 각 await 뒤 요청 ID/세대, 각 OS 조작 직전 잠금·옵션·제외·사용자 조작 여부를 재확인한다.
7. 창별 결과를 같은 요청에 기록하고 하나의 표시 계산을 통해 공개한다.

새 요청·작업 환경 변경·저장 성공·대상 제외·종료의 기존 취소 규칙을 유지한다. 자동 복원 OFF는 자동 요청의 남은 작업에만 적용하며, 수동 요청과 자동 저장은 유지한다. 저장 실패는 새 저장 성공처럼 취급하지 않는다. 이미 OS에 보낸 조작을 취소로 되돌렸다고 표시하지 않는다.

방문 대기 중 다른 Space에서 확인한 사용자 변경의 수집은 허용한다. 단순히 `hasOpenItems`이면 모든 수집을 막는 형태로 바꾸지 않는다. 실행 구간과 화면 안정화 구간만 기존 조건대로 막는다.

### 행동 검증 항목

- 환경 A의 저장본을 A+B에 적용하지 않으며, 화면별 옛 결과도 섞이지 않는다.
- 관찰 중 수동 저장/자동 저장 OFF/환경 전환이 일어나면 늦은 관찰을 폐기한다.
- 저장 실패 뒤 이전 소스·시각·이력·닫힌 자리 제외가 보존된다.
- 방문 대기는 Space 이벤트로 재판정하고 확인 필요는 명시적 재개만 받는다.
- 잠금·잠금 판정 불가에서는 아직 보내지 않은 조작을 중지한다.
- 제외한 앱·저장되지 않은 내장 창·전체화면 창을 잘못 움직이지 않는다.
- 자동 복원 중 사용자가 옮긴 창은 그 요청에서 보호하고 수동 복원에는 자동 보호를 적용하지 않는다.
- 앱 제외는 기록 삭제가 아니며 다시 포함하면 기존 기록이 남는다.
- 자동 복원 OFF와 자동 저장 OFF가 각자 자신의 기능에만 영향을 준다.
- 앱 재실행·권한 획득만으로 복원 요청을 시작하지 않는다.

## 이번 산출물과 검증 범위

`prototypes/product-redesign-2026-10-20.html`은 예시 데이터로 상태와 행동을 검토하는 인터랙티브 시안이다. 실제 창 제어·Space 탐색·파일 저장·권한 변경을 실행하지 않는다. 시안의 이벤트 버튼은 OS 이벤트를 모의한다. JS 자체 검증 및 화면 렌더 확인은 제품 엔진이나 실제 macOS 동작 검증을 대신하지 않는다.

시안 QA: 360px·728px에서 렌더와 가로 넘침을 확인했다. 밝은 카드·어두운 카드 및 방문 대기를 시각 점검했다. 전체 상태 렌더, 후보 선택 후 명시적 재개, 저장 재시도, 첫 저장의 현재 앱 범위, 자동 복원 OFF 시 수동 요청 보존/자동 요청 취소, 실행 중 중복 동작 차단을 브라우저 안의 단언으로 확인했다. 전체 네이티브 앱 빌드나 실기기 검증은 이번 시안 작업의 범위가 아니다.

Claude 검증: 독립 검토는 저장소 밖 `/tmp/plugback-verify-GpVTLQ/repo`에서 현재 문제 동작 5건과 대조 1건을 재현했다. 같은 복사본에서 Swift 패키지 테스트 188개(기존 182 + 재현 6)와 제품 재현 검사 15개 통과를 보고했다. 재현 테스트 원문은 독립 검토 부록 A에 보존했다. 창·Space 입력은 페이크이며, 화면 변경 고착은 실제 해상도 변경 대신 같은 알림을 보내 확인했다. Xcode 앱 테스트와 실기기는 미검증이다. 코드 확인만 한 종료 이중 저장·지문 불일치 자동 저장 등은 재현된 문제와 구분한다.

## 초기 검토의 선택지

아래는 검토 당시의 선택지다. 이번 구현에서는 기존 표시 설정과 기본 동작을 유지하고, 이벤트·결과 소유권부터 정리한 뒤 네이티브 화면을 반영했다. 표시 설정을 없애는 변경은 포함하지 않는다.

1. 하나의 기본 카드에 집중하되 기존 A~D 표시 설정을 당분간 보존할지, 단계적으로 정리할지.
2. 기존 동작은 유지하면서 설명·상태·결과 소유권부터 바꿀지, 제품 기본 동작도 바꿀지. 추천은 전자이며 동작 변경은 별도 근거가 필요하다.
3. 다음 구현 묶음은 결과 소유권/표시 계산부터 시작할지, 화면 시안을 먼저 네이티브로 옮길지. 추천은 결과 소유권/표시 계산이다.

## 구현 반영 — 2026-10-20

사용자가 기획·디자인·아키텍처·구조 개선·리팩토링의 협업 구현을 요청했다. 1번 신뢰성을 기준으로 다음을 작업 트리에 반영했다.

- 이벤트: 안정화 완료를 빠짐없이 통지하고, 복원·재개 실행의 공통 후속 처리에서 화면 전환·잠금 해제·Space 재판정·수집을 처리한다. 원시 화면 변경·취소·제외는 실행 직전 게이트에서 즉시 반영한다. 안정화 중 수동 저장도 막는다.
- 소유권: 요청 결과·시각을 현재 작업 환경에 귀속한다. 후속 작업 환경의 새 요청이 실행돼도 이전 명령의 반환값에는 그 결과를 섞지 않는다. 기존 `lastRestoredAt`의 Combine 구독도 유지한다.
- 창 연결·저장: 같은 창의 환경별 연결과 닫힌 환경을 유지하며 한 환경 안의 일대일 대응은 지킨다. 지문 불일치를 자동 저장으로 갱신하지 않는다. 이탈 저장 실패를 환경별로 보관하고 카드·설정에서 재시도한다. 같은 환경의 재시도 저장 성공은 옛 소스의 남은 요청을 끝낸다. 종료 저장은 한 곳에서 판정한다.
- UI: 상태·다음 행동·저장 기준을 앞에 두고 `CardStatusView`·`CardRequestView`·`CardAppBrowser`로 나눴다. 제외된 자리·지문 건너뜀을 남은 작업으로 세지 않는다. 내장에 모인 저장 창을 외장으로 데려오는 정책은 유지한다. 연결 해제·재실행 뒤에도 기억하는 작업 환경의 화면 이름을 함께 표시한다.
- 사용감: 대기 중에도 다른 동작 메뉴에서 수동 저장·새 복원에 접근한다. 삭제는 한 번 확인하고, 제외와 구별한다. 일반 설정을 먼저 열며 기존 A~D 구성·색·밝기 선택은 유지한다. 수집하지 않은 상태를 「변경 없음」으로 단정하지 않는다.
- 범위: 저장·복원 엔진을 전면 교체하거나 공개 `CoreEvent` 파사드·추가 상태 저장소를 만들지 않았다. 메뉴바 정적 점 표시·알림 권한·새 창 관리 기능은 추가하지 않았다. 기존 작업 환경 파일 형식과 기본값은 유지한다.

실제 구현의 [네이티브 화면 비교](../../prototypes/implemented-redesign-2026-10-20.html)와 README 이미지는 앱 호스트 테스트의 예시 데이터 렌더다. 초기 HTML 시안과 독립 검토는 설계 근거로 남긴다. 케이블 재연결·Mission Control·VoiceOver 실기기 판정은 `DEVICE_TEST_CHECKLIST.md` 11절의 미완료 항목으로 구분한다.
