시뮬레이션이 설계를 바꾼 지점

구멍을 막은 게 아니라, 구멍이 생길 수 없는 모양으로 바꿨다.

변경 1 · S1 S6 S7

활성 슬롯을 없앴다

1차 구멍 3개는 전부 “활성 슬롯이 실제 의도와 어긋난다”였다. 저장된 활성 슬롯 자체를 지우고 더 최근에 저장된 슬롯을 쓰게 하니 어긋날 상태가 없어진다.

복원 소스가 저장된 상태에서 파생 상태로 바뀐다. claimSlot()·화면별 활성 슬롯·끈적임 로직이 통째로 사라진다.

변경 2 · S11

실험실 데이터를 분리했다

자동 슬롯을 profiles.json에 같은 키로 넣으면 설정 창의 allProfiles에 같은 화면이 두 번 뜨고, removeProfile이 자동 슬롯을 안 지운다.

자동 슬롯은 lab-auto.json 별도 파일로. 기존 파일·키·마이그레이션이 0이 되고, 실험을 걷어낼 때 파일 하나만 안 읽으면 된다.

남는 위험 · S5 S10

뽑는 순간의 배치가 정답이 된다

복원이 부분 실패한 상태, 회의하려고 창을 치워둔 상태, 열거가 실패해 옛 위치가 섞인 배치 — 전부 그대로 자동 슬롯에 들어간다.

A안을 고른 이상 받아들이는 위험이다. 답은 회복 경로 4개(S11)와 수동 북마크이지 추가 방어 로직이 아니다.

S1

평범한 도킹 하루

아침에 꽂고, 하루 일하고, 저녁에 뽑는다

통과
09:00케이블 꽂음 → 자동 복원 (더 최근 슬롯)
09:00~앱 전환 수백 회 → 30초 간격으로 후보 갱신 (메모리)
18:00케이블 뽑음 → removed 감지 → 후보를 자동 슬롯에 확정
다음날자동 슬롯이 최신 → 저절로 그걸로 복원
1차 판정 · 구멍 1 — 기능을 켜도 아무 일도 일어나지 않는다
판정

1차에서는 활성 슬롯이 수동에 머물러 자동 슬롯을 아무도 안 썼다. 최신순 규칙에서는 자동이 최신이면 저절로 이긴다. 켜는 것 말고 할 일이 없다.

“저장을 잊어도 되는 앱”이 이 시나리오에서 성립한다. 그리고 이걸 위해 새로 저장하는 상태가 하나도 없다 — 슬롯 두 개의 저장 시각에서 파생될 뿐이다.

S2

오늘 Slack을 안 켰다

US-002 AC-4 — 꺼둔 앱이 프로필에서 사라지면 안 된다

막힘
전제수동 슬롯 = { Chrome, VSCode, Slack }
09:00복원 → Slack은 appNotRunning으로 건너뜀
하루Chrome·VSCode만 사용 → 후보에 Slack이 없다 (창이 없으니)
18:00확정 → capture(merging: 자동 슬롯)
판정

병합 대상이 빈 자동 슬롯이었다면 Slack이 사라진다. 다음날 자동 슬롯으로 복원하면 Slack이 안 돌아온다 — US-002 AC-4가 깨진다.

이미 막혀 있다. “실험실을 켤 때 수동 슬롯을 자동 슬롯으로 복사한다”는 규칙 덕분에 자동 슬롯이 처음부터 Slack을 갖고 있고, 병합이라 지워지지 않는다.

그 한 줄이 여기서 정당화된다. 안 해뒀으면 이 시나리오에서 깨졌다.

1.5초를 넘겨 진짜 분리로 판정되면: 확정 → 재연결 → 자동 슬롯이 최신이니 그걸로 복원. 방금 확정한 값이라 전부 alreadyInPlace다. 창이 흔들리지 않는다.

S5

복원이 실패한 채로 하루를 보냈다

A안을 고른 이상 남는 위험

수용
09:00복원 → VSCode 이동 실패(.failed). 창이 엉뚱한 자리
하루눈치 못 챔 (혹은 손으로 대충 옮김)
18:00확정 → 엉뚱한 자리가 자동 슬롯에 기록됨
다음날자동이 최신 → 엉뚱한 자리로 복원
판정

진짜 위험이고, 자동 저장을 프로필에 쓰기로 한 이상 받아들인다. 허용 오차 규칙은 드리프트만 막는다 — 이건 값이 커서 안 걸린다.

회복 경로가 네 개 있다(S11). 가장 짧은 건 수동 저장 버튼 한 번 — 누르는 순간 수동 슬롯이 최신이 되어 다음 복원이 그쪽으로 간다.

“실패가 있었으면 확정 건너뛰기”는 넣지 않는다. 사용자가 손으로 고쳤을 수도 있고, 그 경우엔 고친 결과를 버리게 된다. 판단이 필요한 지점은 사람에게 남긴다.

S6

실험실을 켰다가 껐다

기능을 끄는 경로가 상태를 남기는지

통과
켬수동 슬롯을 자동 슬롯으로 복사 (S2가 요구한 씨앗)
하루자동 슬롯 갱신됨. 자동이 최신이라 복원에 쓰임
끔알림 구독 해제 · 자동 슬롯이 비교에서 빠진다 → 수동 슬롯만 남음
1차 판정 · 구멍 2 — 껐는데 자동 슬롯에 갇힌다
판정

1차에서는 “활성 슬롯을 강제로 수동으로 되돌린다”는 보정이 필요했다. 최신순 규칙에서는 “꺼진 기능의 슬롯은 비교에 참여하지 않는다” 한 조건으로 끝난다.

같은 결과인데 설명이 더 짧다. 강제로 상태를 되돌리는 게 아니라, 애초에 후보에서 빠지는 것이다. 자동 슬롯 파일은 그대로 남아 다시 켜면 이어진다.

S7

저장한 뒤에 창을 옮기고 뽑았다

1차에서 가장 컸던 구멍이 스펙이 된 자리

스펙 변경
15:12창을 마음에 들게 배치 → [💾 지금 레이아웃 저장] → 수동 슬롯
16:00계속 일하며 창을 옮김
18:00뽑음 → 자동 슬롯 = 18:00 배치 → 자동이 최신
다음날18:00 배치로 복원. 15:12 저장은 수동 슬롯에 그대로 살아 있다
1차 판정 · 구멍 3 — “저장했는데 왜 안 돌아와?”
판정

1차에서는 이걸 구멍으로 봤다. 재검토 결과 구멍이 아니다. 저장 후에 창을 옮겼다면 옮긴 쪽이 더 최근의 의도다. 수동 저장이 영구히 이기면 결국 “언제 저장을 눌렀는지”를 기억해야 하는 앱으로 돌아간다.

수동 슬롯의 역할이 재정의된다 — 기본값이 아니라 되돌아갈 북마크다. 사라지지 않고, 카드 메뉴에서 언제든 1회성으로 복원할 수 있다.

대가 — 저장한 배치를 계속 쓰려면 그날 창을 크게 옮기지 않거나, 실험실을 끄면 된다. 드리프트 방지(5px) 때문에 미세 조정은 애초에 안 잡히므로, 실제로 문제가 되는 건 큰 이동뿐이다.

S10

어떤 앱의 창 열거가 실패한다

실측으로 확인된 사건 — 8b21eaa

수용
실측재연결 순간 Aside 열거 실패, 평시에도 Fork 1회 (2026-08-18)
현재250ms 초과 시 1초 한도로 1회 재시도. 재시도까지 실패한 앱만 빠진다
수집그 앱이 후보에서 빠짐 → capture가 병합이라 옛 위치가 살아남는다
확정그 앱만 아침 위치, 나머지는 저녁 위치 — 시각이 섞인 배치
판정

새 구멍은 아니다. 병합의 기존 성질이고 수동 저장도 오늘 똑같이 동작한다. 그리고 8b21eaa의 재시도는 이 확률을 줄인다.

다만 “실제로 일어나는 일”이 실측으로 확인됐으므로 기록해 둔다. 손실은 없다 — 항목이 지워지는 게 아니라 오래된 값이 남는 것이고, 수동 슬롯은 무관하다.

비용 갱신 — 앱당 최악 열거 시간이 250ms에서 1.25초가 됐다. 수집이 앱 전환마다 도는 만큼, 최소 간격 결정의 입력값이 바뀌었다.

S11

실험이 실패했다 — 되돌릴 수 있나

실험실 기능의 전제조건

통과
경로 1수동 저장 한 번 → 수동이 최신이 됨 → 다음 복원이 수동으로. 가장 짧다
경로 2카드 메뉴 “수동 저장으로 복원” → 1회성. 지금 당장 되돌린다
경로 3실험실 OFF → 자동 슬롯이 비교에서 빠짐. 오늘의 앱과 동일한 동작
경로 4lab-auto.json 삭제 → 완전 초기화. profiles.json은 무관
기능 제거코드에서 걷어내면 그 파일을 안 읽을 뿐. 마이그레이션 0줄
판정

이 시나리오가 저장소 설계를 바꿨다. 자동 슬롯을 profiles.json에 screenID#auto 같은 키로 넣으면 되돌리기가 깨진다 — 설정 창의 allProfiles가 같은 화면을 두 번 표시하고, removeProfile(screenID)가 자동 슬롯을 안 지운다.

별도 파일로 두면 기존 파일도, 키도, 마이그레이션도 건드리지 않는다. ProfileStore에 파일명 파라미터 하나(2줄) 추가하면 클래스를 그대로 재사용한다.

손상 처리도 분리된다. profiles.json의 백업·초기화 로직과 saveBlocked 판정이 실험 때문에 흔들리지 않는다. 실험실 파일이 안 읽히면 자동 슬롯이 없는 것으로 취급하면 그만이다.

1차의 구멍 3개를 없앤 규칙

복원 소스는 저장하지 않는다. 더 최근에 저장된 슬롯이 이긴다.
  • 자동이 최신 — 켜두면 저절로 쓰인다. 활성 슬롯을 손댈 일이 없다 (구멍 1)
  • 실험실 OFF — 자동 슬롯이 비교에서 빠진다. 강제 되돌림이 필요 없다 (구멍 2)
  • 저장 뒤 이동 — 옮긴 쪽이 더 최근의 의도다. 구멍이 아니라 스펙이다 (구멍 3)
  • 한쪽만 있음 — max가 알아서 그쪽을 고른다. 폴백을 따로 짜지 않는다
  • 둘 다 없음 — 복원 자체를 하지 않는다. 기존 동작 그대로 (US-007 AC-5)

시각은 이미 필요했다 — 카드가 슬롯마다 저장 시각을 보여줘야 하기 때문이다. 그 값을 비교에 쓰는 것뿐이라 새 상태가 늘지 않는다.

남은 결정

수집 최소 간격 — 30초?

자동 슬롯은 “마지막 앱 전환 시점”의 배치이므로 간격이 곧 오차 상한이다. 8b21eaa로 앱당 최악 열거가 1.25초가 됐으니, 짧게 잡으려면 이 비용을 먼저 실측해야 한다.
